# 技术设计：球队页一键清除小组筛选

## 方案摘要

在球队页现有筛选入口旁新增原生清除按钮，共用“全部小组”的重置逻辑。沿用原生 JavaScript、Vite、Vitest/jsdom 和 Playwright。功能为轻量 UI 变更。

## 变更地图

| 位置 | 职责 |
| --- | --- |
| src/views/teams.js、public/i18n/{zh,en}.json | 渲染默认隐藏的按钮，使用现有 t() 提供双语文案 |
| src/teams-filter.js | 在稳定的 #app 根节点委托清除事件，与原筛选同步逻辑共用状态更新，沿用初始化去重和释放 |
| src/styles/pages.css | 复用筛选控件视觉和 tokens.css 的主题变量，保证窄屏间距、触控区域和焦点样式 |
| tests/teams-dropdown.test.js、e2e/teams-dropdown.spec.js | 扩展现有单测及浏览器回归 |

## 关键决策

由当前具体小组的勾选状态派生按钮可见性。重置全部勾选和列表后将焦点移至当前筛选入口，防止焦点落到页面主体。按钮位于面板外，与入口同一控件行，面板关闭后仍能清除。保留现有外部点击关闭规则与语言切换重渲染行为。筛选状态、事件与焦点归球队页，聊天区域不参与。沿用球队卡片、国旗和详情链接。

## 待确认项与风险

无阻塞规划的需求问题。无外部设计稿，采用规格文字和现有球队页作为设计依据。编码前核对入口与按钮的布局及键盘顺序。实现后用当前构建核对窄屏两控件不会互相遮挡，面板关闭与隐藏按钮不会造成焦点丢失。QA 的具体设备与浏览器版本在实际验收时记录。

## 技术上下文与宪法检查

现有 Hash 路由和静态数据足够。状态限于页面生命周期，无新增存储、接口或迁移。双语词条成对维护，语言切换后按现有规则重渲染并验证默认状态。研究前与设计后核对了现有规则，设计保留真实 TDD、覆盖率、双语与人工交接约束。开发时先写行为测试，实际观察因功能缺失导致的断言失败，再完成实现及回归，按需重构。

覆盖率以实施前确认的 Git 基线比较本功能新增或修改的自有 JavaScript 可执行语句起始行。使用 npm run test:coverage 采集 Vitest 单测结果，以现有 addedLines 差异算法与 coverage/coverage-final.json 计算未舍入 C/D ≥ 80%，基线源码从 Git 读取，排除纯样式、词典和测试文件。缺少可靠采集时记录能力缺口。浏览器和人工结果不计入该比例。当前两个 HTML 报告开关均停用。
