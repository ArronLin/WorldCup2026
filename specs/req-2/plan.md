# 实施计划：积分榜排序

**仓库** `worldcup-2026`（仓库 2） · **实施分支** `req/1-group-standings-sorting` · **日期** 2026-11-26 · **输入** [积分榜排序规格](spec.md)，规格 5，变更代次 2。

## 摘要

在每个已展示小组的分数、进球数、失球数和净胜球数表头加入按钮。首次选择或切换指标时，失球数默认升序，其余三项默认降序。重复选择当前指标时翻转方向。只重排目标表格已有的球队行，保留名次、统计、详情链接和静态快照说明。排序状态随本次页面使用结束而释放。

## 技术背景与范围

项目是采用原生 JavaScript ES Modules 和 Vite 的中英文浏览器单页应用，使用 Node.js 24 或以上以及 `package-lock.json`。积分榜读取静态赛事 JSON。视图通过 `getStandings()` 获得 A 至 L 各组的初始记录。沿用 Vitest、jsdom 与 Playwright。一次操作仅排序目标小组的 n 条记录，设计复杂度为 O(n log n)，暂存 O(n) 条行引用。排序在浏览器内完成，无新增第三方依赖、服务、网络请求、数据迁移或偏好持久化。

## 快速验证指南

1. **准备环境。** 在实施分支确认 Node.js 24+，执行 `npm ci` 并记录退出状态。按现有脚本参数选取变更前 Git 提交或执行 `npm run coverage:baseline` 建立源码基线。首次缺少 Chromium 时执行 `npx playwright install chromium`。
2. **验证规则与视图。** 逐行为先运行 `npm test -- tests/standings-sort.test.js` 或 `npm test -- tests/group-standings-view.test.js`。确认实际执行的目标断言因功能缺失而失败，再最小实现、复跑并按需重构。修复依赖、导入和收集错误后重新取证。使用冻结输入验证真实生产逻辑，断言 2、9、10 的两种方向与净胜球 2、0、-1、-3 的完整顺序。构造两个无效值、真实零和并列队，切换指标打乱顺序后再切回，核对两种方向的并列顺序、无效值置后、球队集合、统计及原数据。对空组、单队和全同值组核对记录数与适用的方向提示。
3. **执行 T005 专项浏览器验收。** T004 完成后执行 `npm run build`，在该构建的独立预览上运行 `npm run test:e2e -- e2e/standings-sort.spec.js`。使用固定输入的真实页面，分别建立 Enter 键和空格键两个独立用例。每例从未排序状态开始，用 Tab 聚焦“分数”表头按钮，用该例对应键连续操作两次。第一次应为分数降序、`aria-sort="descending"`、↓，第二次应为升序、`aria-sort="ascending"`、↑。每次按键均核对恰好触发一次排序、焦点仍在原按钮、唯一活动表头及箭头正确，并逐行比对完整预期球队顺序。可在测试侧观察活动表头的 `aria-sort` 写入次数和状态变化，分别保留两个用例的结果。另以指针操作四列，核对双语提示、原名次、详情链接及赛事来源说明。先让 A 组按分数降序、B 组按失球数升序，再改选并翻转 A 组指标，每次均比对 B 组的球队、统计、行序和排序提示。分别在无 AI 配置、受控 AI 请求实际返回服务错误的环境中进入积分榜，操作四列，核对完整数据、行序及方向，排序期间新增 AI 请求数应为零。
4. **执行 T006 全量回归。** T005 完成后在当前工作区执行 `npm test`、`npm run build`。构建成功后记录工作区绝对路径及构建产物标识（如 `dist/index.html` 与其引用的带哈希资源清单），确认 `127.0.0.1:4173` 空闲。若端口占用，记录阻塞，待空闲后重试。仅为本次 Playwright 运行设置 `CI=1`，由 `npm run test:e2e` 启动独立预览并执行全量回归。在 Windows PowerShell 中可用 `cmd.exe /d /c 'set "CI=1" && npm run test:e2e'` 将设置限定在子进程内。保留预览启动日志、实际工作区路径、构建产物标识及全量回归退出码，对照响应的页面及资源标识确认所测版本。启动失败或版本不符时记录失败原因，修正后重跑。
5. **核算覆盖率并核对任务。** 运行 `npm run test:coverage` 并用 `npm run coverage:added` 对照 T001 基线。验收采用变更范围内单元测试命中的分支结果数除以纳入的分支结果总数，默认至少 **80%**。纳入比较、指标选择、方向转换、有效性、界面状态和事件处理中的新增或修改分支。纯声明式标记、翻译文本和 CSS 按实际内容说明排除理由，通过页面断言验证。核对 V8 分支明细、变更位置、分子及分母。无法可靠归属时记录未核验及原因。T006 运行 `inspect-tasks`，记录实际输出、检查范围、T001–T006 每项状态及全部未完成项编号，逐项比对原生任务清单；核对两份清单中的 T005 范围、依赖、键盘用例和 T006 独立预览条件。发现遗漏或差异时记录并复查。通过、失败、跳过及待人工签认分别记录。

本次计划未执行构建、单元测试、浏览器测试、覆盖率采集或任务收尾检查。
