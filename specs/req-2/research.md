# 积分榜排序设计依据

本次依据为仓库 `worldcup-2026`（仓库 2）的冻结快照，摘要为 `6c9d824d12286a5c0975e7f369ee7a65150c6b4ce9d4de2025198bbe72405a65`。研究前核对了候选宪法条款-001、002、008。排序须保留赛事快照说明，且在 AI 不可用时仍可使用。此次变更不涉及条款-003、004 所述的会话外传或密钥处理，无已批准例外。

| 决定 | 依据与理由 | 考虑过的方案 |
| --- | --- | --- |
| 以视图收到的每组球队序列为初始顺序，直接读取已有统计 | 已按既有 CodeGraph 定位核对冻结源码 `src/views/group-standings.js`。`standingsView` 等待 `getStandings()`，遍历 A 至 L，跳过空组，按输入顺序生成球队行。四个普通表头对应 `points`、`goalsFor`、`goalsAgainst`、`goalDifference`。 | 重新计算赛事积分会扩大范围，还可能改变名次含义。该视图没有调用 `calcStandings`。 |
| 每张组卡片保存自己的状态，移动已有球队行 | 视图返回 HTML 字符串。原生自定义元素可承载 `.group-card`，按初始行序建立固定索引，连接时监听表头操作，断开时释放监听。移动表体内的行可保留表头焦点、球队详情入口及资格样式。 | 全页重绘需要恢复焦点，全局共享状态容易干扰其他小组。 |
| 用纯函数计算方向与行序，视图显示缺失提示 | 源码将这四项统计的空值回退为零，与 AC7 冲突。只为原始有限数值生成排序键。依次比较有效性、有效数值、初始序号，只有数值比较随方向翻转。 | 解析展示文本会混入正号或缺失提示，整体反转会反转并列球队的顺序。 |
| 沿用 Vitest、jsdom 和 Playwright | 冻结的 `package.json` 已声明这些依赖，`vite.config.js` 从 `tests/**/*.test.js` 发现单测。`playwright.config.js` 从 `e2e` 发现浏览器用例，使用 `127.0.0.1:4173` 并通过 `npm run preview -- --host 127.0.0.1` 启动预览。`reuseExistingServer: !process.env.CI` 允许无 CI 标志时复用服务。 | 既有冒烟用例不足以证明四项排序、双组隔离或 AI 故障下的行为。复用已有预览也无法保证所测版本。 |

默认方向、重复选择和切回行为来自产品负责人决定。同值、缺失及组间隔离按冻结规格执行。评审已确定共享工作区安装顺序、T004 至 T006 的交付顺序、两个键的独立用例、全量回归的独立预览和 `inspect-tasks` 收尾要求。具体执行条件见 [实施计划](plan.md)。本阶段未运行实现测试。
