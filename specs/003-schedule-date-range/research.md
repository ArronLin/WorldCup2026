# 技术研究：赛程日期区间筛选

本次研究沿用输入控件、日期比较、状态生命周期和覆盖率采集决定，并依据规格 2026-11-10 澄清更新 R4 的焦点与草稿保留方案。既有标准来源继续适用；本轮补查当前路由、语言和事件入口，没有运行应用或测试。

## R1：使用可保留原文的日期输入

**决定**：使用两个文本输入，显式提示 `YYYY-MM-DD`；每次输入立即保存原始草稿，应用时才校验。不自动裁剪空格、交换日期或截断输入，不设置 `maxlength=10`。非空值要求四位年份 `0001`—`9999`；这是本功能格式选择，不是 HTML 日期语法的全部取值范围。

**理由**：规格 FR-003、FR-006 要求非法和不完整输入在语言切换及重渲染后保留。原生日期控件会把非法日期值清洗为空，`badInput` 不提供可用于重建的原始文本；文本输入能保留草稿。[WHATWG 日期输入](https://html.spec.whatwg.org/multipage/input.html#date-state-(type=date))、[WHATWG 文本输入](https://html.spec.whatwg.org/multipage/input.html#text-(type=text)-state-and-search-state-(type=search))。

**备选**：原生日期选择器省去部分交互，但不能可靠恢复非法草稿；保留原控件 DOM 则要求改变当前整页渲染机制。此前文本输入方案没有日历弹层。2026-11-11 用户确认增加特性内日历选择并保留手写与应用机制；因此保留文本字段，另加非模态日历弹层，按数值计算公历，不依赖原生日期控件清洗或时区转换。复用 `t()`、月份词条及语义主题变量；现有旗帜、徽标、比赛卡片与图标不提供日期选择组件，因此新增特性模块。弹层使用视口内固定定位，避免靠近底部时被裁切。

## R2：按公历验证，再按日期字符串比较

**决定**：在无 DOM、语言或时区依赖的 `date-range.js` 中实现真实日期验证；空值表示无边界，非空值依次检查格式、年份、月份和实际天数。闰年采用能被 400 整除，或能被 4 整除但不能被 100 整除的规则。两端合法后才比较先后；规范化日期直接按字符串顺序比较，不用 `Date.parse()` 或时间戳。[WHATWG 日期语法](https://html.spec.whatwg.org/multipage/common-microsyntaxes.html#dates)。

**备选**：用 `Date` 构造后回读需要处理溢出归一化、时区和小年份行为；引入日期库对当前范围没有必要。生效摘要在特性视图内按年月日分量与 `t()` 生成，展示函数不参与匹配。现有 `formatDateFull` 的本地午夜转换会在 Pacific/Apia 将 `2011-12-30` 显示为次日，因此不用于该摘要；格式及验证边界以 [接口契约](contracts/schedule-date-range.md#日期摘要) 为准，共用工具及其他页面保持原有范围。

**契约缺口**：当前 `getTournamentSnapshot` 不校验日期，发布校验仅要求日期为字符串。两处应复用上述纯验证器：运行时返回既有 `invalid-data`，发布时阻止非法快照，不把坏数据解释成零场。当前 104 条日期经只读检查均为真实 ISO 日期；该检查不等于发布脚本或新增功能测试通过。

## R3：日期状态与关注状态分开

**决定**：新建仅驻留内存的日期状态对象，分别保存草稿、生效值和错误代码。赛程视图先调用既有 `selectMatches` 得到关注／阶段交集及去重结果，再应用日期过滤，保留原顺序。日期模块不写存储，不改 `createFollowState`、既有 `selectMatches` 签名或关注记录版本。

**备选**：给关注状态增加日期字段会使球队详情及持久化职责混杂；把所有筛选另起一套实现则重复去重、阶段和关注逻辑。分离状态并组合纯筛选，变更范围较小。

## R4：在实际导航和已提交渲染上接入生命周期

**决定**：路由增加轻量订阅入口，分别通知目标路径变化和最新页面提交。日期控制器订阅导航，仅从赛程路径离开时清除草稿／错误；同页语言或筛选重绘不清。提交通知发生在新 DOM 写入之后、焦点恢复之前，用于把最新草稿写回输入 `.value` 并刷新提示。用户输入不触发整页重绘。

**理由**：当前 `handleRoute` 替换 `#app.innerHTML`，已有 `navigationId` 防止旧请求提交；仅在视图销毁时清草稿会把语言重绘误判为离页。仅保存到 DOM 则不能跨重绘恢复。事件处理前先改状态，渲染后取最新状态，可避免等待期间的新输入被旧渲染覆盖。

**备选**：单独监听 `hashchange` 会和路由的路径判定及异步顺序重复；重写路由为增量渲染超出本次需要。订阅 API 不直接依赖功能模块，保留原路由调用兼容性。

**澄清后的决定**：所有应用操作（包括无效提交）及清除都同步修改状态后进入同一缓存重绘序列；渲染完成只读最新状态，不能再次清除错误、关闭未应用提示或用提交快照覆盖新草稿。较新无效提交保留最近有效结果及本次错误；过期请求不能产生恢复或播报副作用。

焦点由可选 `resolveFocusTarget` 在替换旧 DOM 前解析，返回候选与默认目标；新 DOM 同步当前草稿后再核验目标可用性。原焦点白名单只覆盖关注控件，不能满足澄清后的“最新仍可用控件”：需补日期、比赛 ID、空态链接及重建导航的稳定身份，并保留未替换外壳控件的实际引用。最新目标消失、禁用或隐藏时才回退该次操作的默认目标；接口细节集中在 [契约](contracts/schedule-date-range.md)。

**接入边界**：日期、阶段、关注、重试及语言的赛程同页刷新共用选项包装器；否则较新的旧调用路径仍会抢回焦点。`toggleLang()` 在词典加载后才触发 `langchange`，因此语言按钮激活时就要捕获操作上下文，后来的输入或移焦不能被等待词典的时间窗口遗漏。沿用 i18n 的最新请求保护，不重做语言状态系统。

**备选与影响**：始终聚焦提交按钮／错误字段违反已确认的 A；只增加四个日期键会漏掉卡片和外壳；仅返回键或空值无法区分可用外壳与失效目标。采用受限目标描述及现有 `refresh` 注入入口，增加焦点边界验证，保留普通路由调用兼容性，不改为增量渲染框架。

## R5：错误代码本地化与持久播报区

**决定**：错误存代码，渲染时通过 `t()` 获取文字；用标签、`aria-describedby`、`aria-invalid` 表达输入与错误关系，失败默认聚焦首个无效字段，后续主动操作按 FR-007 优先处理。使用普通文本输入键盘，允许连字符。草稿只通过 DOM `.value` 写入，提示只通过 `textContent` 更新，不把任意输入拼进 HTML 属性。[W3C 表单反馈](https://www.w3.org/WAI/tutorials/forms/notifications/)。

数量播报使用 `#app` 外的持久 `role="status"` 区域，页面提交后更新；可见数量仍在赛程页，移除其重复播报角色。原区域随整页替换而重新创建，不能仅凭其存在证明每次更新都可播报。错误通过关联文本与聚焦解释，不创建模态窗口。

## R6：复用现有覆盖率算法，增加不落盘源码的基线模式

**决定**：保留现有旧模式，增加 `--base-commit` 从 Git 对象读取基线到内存；新增 `--audit-sources` 明确工程脚本采集范围。业务与工程脚本分别计算相同的变更行指标，避免互相稀释；基线及分母见 [计划](plan.md)。

**理由**：当前 `coverage:baseline` 读取历史 manifest 并重建源码副本，`coverage:added` 默认输出到旧功能目录；现行规则要求不生成源码副本。现有源码映射、LCS、语句起始行、覆盖数据一致性和哈希校验可继续使用，不能直接把旧流水线输出当成本功能结果。

**备选**：全项目覆盖率不符合变更范围口径；创建新的一套审计工具会重复已有算法。最小适配范围为两个现有脚本、一个声明式配置及其测试，保持旧 manifest、默认生产路径规则和 CI 入口兼容。此能力尚待实现和验证，当前覆盖率保持未核验。
