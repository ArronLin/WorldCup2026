## 评审摘要

- **方案摘要**：沿用独立日期特性、文本输入及公历比较方案；保留刷新期间的新草稿和最新可用焦点。本轮修正生效日期摘要的时区独立性，并明确分步实现的测试完成边界。
- **变更地图**：日期摘要在特性视图内按年月日分量本地化，补充双语与跨时区断言；同步接口契约、研究取舍和现有任务清单，保留 T001—T036 编号及依赖。日期过滤、数据校验、焦点与覆盖率适配范围继续保留。
- **关键决策**：状态在提交时同步更新，刷新完成只读最新快照；焦点在旧 DOM 替换前捕获、新 DOM 回填后校验。摘要不经过本地时区转换；T016 验证独立视图，T017 验证控制器集成，T018／T019 完成 US1 回归。
- **需确认项**：规格澄清已确认焦点优先级，没有新增阻塞规划的业务问题。界面仍沿用规格中的文字方案，编码前按既有约定核对设计确认范围；本计划不扩展为视觉批准。
- **主要风险**：日期展示改变生效端点、混合测试范围阻塞分步实现，以及遗漏焦点身份或让旧完成回调重置新草稿。分别以日期摘要契约、明确的测试子集和既有竞态验证处理；原数据校验、覆盖率及历史截图风险继续按既有安排验证。

## 技术设计与集成顺序

### 日期规则与状态边界

先实现可独立验证的纯日期规则及状态模型，具体字段和转换以 [数据模型](data-model.md) 为唯一归属。草稿保存原文，错误保存代码；只提交合法区间。输入空值不等于非法快照日期，不同入口明确区分。

数据层在返回 ready 前校验每场日期，非法时沿用 `matches/invalid-data`，重试逻辑不变。发布脚本直接复用同一纯验证器，并保留比赛 ID、球队及双语校验。当前日期合法，无需迁移快照。

赛程取得 ready 数据后读取最新关注与日期快照，再顺序执行现有筛选和日期过滤。仅处理范围筛选，不复制去重或排序；渲染计数、卡片及摘要使用同一轮状态。存储失败提示、无关注球队优先级、无匹配提示及重试入口复用原实现。

生效区间摘要由特性内 `view.js` 按合法日期的年月日分量和 `t()` 双语词条生成，不构造 `Date`、时间戳或依赖设备时区。现有 `formatDateFull()` 采用本地午夜，不能保证所有允许日期原样展示，因此此摘要使用特性内格式化；共用工具及既有调用方不在本次修改范围。输入、格式及空端点处理集中在 [接口契约](contracts/schedule-date-range.md#日期摘要)，该展示逻辑纳入业务变更行覆盖率。

### 事件、导航与异步刷新

稳定 `#app` 上委托输入、提交和清除；文档级焦点监听覆盖页面及外壳，以 WeakMap 避免重复初始化并完整解绑。输入事件只同步草稿和局部提示，不替换控件。所有提交（含无效）及清除先同步更新状态和当前控件，再请求缓存刷新；无效提交保留生效结果，通过新请求使之前的成功刷新失效。成功提交清的是提交前错误，不能在等待结束后再次清状态。

路由提供目标导航及最新页面提交的通知，功能层只在真正离页时丢弃草稿。新 DOM 写入后从当前快照回填原文、错误和派生 `dirty`；新草稿不同于生效条件时保留未应用提示，列表、数量及摘要仍使用最近有效条件。渲染与焦点恢复均不得把旧草稿快照重新写回模型。路由继续以 `navigationId` 仲裁，控制器不另建渲染队列。

`resolveFocusTarget` 在确认最新请求后、旧 DOM 替换前捕获最新焦点意图；回填之后才检查目标的连接、可见、可操作及实际聚焦结果，失效才回退本次默认目标。身份覆盖日期、原筛选、按比赛 ID 标识的卡片、空态链接和导航；外壳未替换的控件保留实际引用。恢复与必要选区处理在受请求身份保护的同步提交段完成，不放在 `await refresh()` 之后。目标描述与默认目标规则集中在 [接口契约](contracts/schedule-date-range.md)。

新控制器导出的 `withScheduleDateFocus` 为所有赛程同页刷新装饰选项：日期操作直接使用；现有关注控制器通过已有 `refresh` 参数接入，不改关注状态或其接口；语言链路也使用该包装器。语言按钮激活时、调用异步 `toggleLang()` 前记录默认目标与意图版本，不能等 `langchange` 才捕获；词典等待期间继续编辑或移焦同样优先。外壳重建前准备刷新选项，过期语言操作和实际离页不恢复旧意图。

语言文案及日期摘要继续通过 `t()` 接入既有语言刷新链路，主题仅改属性。新增焦点键同时纳入允许规则及精确目标匹配；日期操作保留滚动。草稿通过 `.value` 回填，用户原文不拼入 HTML 属性；焦点和错误关联接受 DOM 与浏览器验证。
