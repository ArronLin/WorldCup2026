# 数据模型：赛程日期区间筛选

本功能新增会话内日期状态，复用比赛和关注数据，不引入持久化实体。业务含义以 [规格](spec.md) 为准；纯模块位置与集成方式见 [计划](plan.md)。

## 日期状态

| 字段 | 类型与初值 | 约束 |
| --- | --- | --- |
| `draft.start`、`draft.end` | 字符串，均为 `''` | 保存单行输入原文，允许暂时不完整或非法，不裁剪空格或截断 |
| `applied.start`、`applied.end` | 字符串，均为 `''` | 只能是空值或通过校验的 `YYYY-MM-DD`；双端非空时开始不晚于结束 |
| `errors.start`、`errors.end` | `null` | 取值为 `null`、`invalid-date`；结束字段还可为 `reversed-range` |
| `dirty` | 派生布尔值 | 任一草稿原文与对应生效值不同时为真，不另存独立状态 |

快照须复制嵌套对象，调用方不能修改内部状态。错误保存代码而非中文／英文消息；`dirty` 和错误相互独立，因此回改到生效值可消除未应用提示，但已有错误按规格假设保留至再次应用、清除或离页。

## 日期值与验证结果

有效日期严格采用四位年份 `0001`—`9999`、两位月份和两位日期；空字符串只在区间端点中表示无限制，不是有效的比赛日期。单端错误不产生区间倒置错误，两端合法后才能检查先后。

`validateDateRange(draft)` 返回两类结果：

- 成功：`{ ok: true, range: { start, end } }`，不转换为时间戳。
- 失败：`{ ok: false, errors: { start, end }, firstInvalid: 'start' | 'end' }`，保留原草稿，按开始、结束的阅读顺序确定默认错误焦点。

`invalid-date` 对应“请输入有效日期”；`reversed-range` 对应“结束日期不能早于开始日期”。错误文字统一由词典提供。

## 状态转换

| 操作 | 草稿 | 生效值 | 错误 | 外部影响 |
| --- | --- | --- | --- | --- |
| `setDraft(field, value)` | 更新指定原文 | 保留 | 保留 | 局部更新未应用提示，不筛选、不请求网络 |
| `apply()` 成功 | 保留提交时的合法原文 | 原子替换两个端点 | 同步清空提交前错误 | 请求一次页面刷新，默认焦点为应用按钮；不在刷新完成时再次清状态 |
| `apply()` 失败 | 保留 | 保留 | 同步替换为本次校验结果 | 以原生效条件重绘，默认焦点为首个无效字段；新请求使前次异步刷新失效 |
| `clear()` | 同步清空两项 | 同步清空两项 | 同步清空 | 立即刷新结果；默认焦点为清除按钮，重复调用结果相同；后续编辑仍可产生新草稿 |
| 最新刷新完成 | 保留当前原文 | 保留 | 保留当前代码 | 只将最新快照同步到 DOM，不再次执行应用、清除或丢弃草稿 |
| `discardDraft()` | 复制生效值 | 保留 | 清空 | 实际离开赛程时调用，不触发页面刷新 |
| 同页语言／主题变化 | 保留 | 保留 | 保留代码 | 文字按新语言生成；主题不改状态 |
| 整页刷新／新标签页 | 初始值 | 初始值 | 初始值 | 由新模块实例建立，不读取日期存储 |

表中默认焦点仅在没有后续主动操作，或最新目标已不存在／不可操作时使用；优先级和目标识别见 [接口契约](contracts/schedule-date-range.md)。

### 刷新等待期间的不变量

- 状态转换在请求刷新之前同步完成。后续 `setDraft` 只改变草稿；较早提交的完成回调不得把 `applied` 或提交快照重新写入 `draft`，也不得清除后来产生的错误。
- 未应用提示始终由当前 `draft` 与当前 `applied` 的比较产生，不由“刷新成功”关闭。新草稿不同于生效值时显示，改回相同值时消失；列表、数量及摘要只使用最近有效提交的条件。
- 焦点意图属于控制器的短期交互上下文，与业务快照分开；移焦不应用草稿、清错误或改变筛选。过期请求不产生 DOM、状态、焦点或播报副作用；真正离页仍按 FR-006 放弃草稿。

## 比赛与组合结果

沿用比赛的 `id`、`date`、`stage`、`round`、`group`、`home.code` 和 `away.code`。先用既有关注／阶段选择器去重，再按生效日期过滤，既不修改输入数组，也不重排比赛。摘要和数量来自同一轮生效日期与关注状态快照。

运行时 `getTournamentSnapshot` 在既有结构／引用校验上增加 `date` 的真实日期约束，失败仍为 `{ status: 'error', dataset: 'matches', kind: 'invalid-data' }`。发布校验复用同一验证器，报告比赛标识及日期问题；不为非法日期补值或自动迁移数据。

## 导航生命周期

日期状态不保存路由和 DOM。控制器使用路由事件判断 `/schedule` 与 `/schedule/`；两者之间切换仍属于赛程。真正离开时调用 `discardDraft()`，返回时保留 `applied`。同页重绘、数据重试均不触发离页转换。已提交渲染的通知负责恢复最新草稿，旧异步请求不能恢复旧状态。

## 持久化与兼容

日期状态无存储键、序列化版本或跨标签页同步。`wc2026-followed-teams` 的版本及球队代码记录不变；关注存储失败的提示继续使用既有逻辑。比赛快照、路由、聊天协议均不迁移。日期合法性检查收紧的是既有字段的消费约束；当前 104 条日期均符合，后续非法数据应显式报错。
