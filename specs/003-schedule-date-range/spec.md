# 功能规格：赛程日期区间筛选

**功能目录**：`specs/003-schedule-date-range`

**当前分支**：`main`（本次未创建功能分支）

**创建日期**：2026-11-10

**状态**：日历赛事边界已实施并完成本地验证（2026-11-11），实际范围见任务清单

**输入**：[赛程日期区间筛选需求](../../requirements/schedule-date-range.md)

## 评审摘要

- **用户价值**：用户按某一天或连续日期范围缩小赛程，减少逐场核对日期的操作。
- **主要变化与范围内**：在现有赛程页增加日期输入、主动应用、校验、单独清除和结果反馈，与阶段及关注球队条件组合；覆盖状态保持、中英文、键盘和窄屏使用。
- **范围外**：整页赛程日历月视图（不含日期输入弹层）、日期快捷预设、时区换算、日历导出、提醒、登录、云同步及可分享的日期筛选链接。
- **关键决定**：按静态快照的比赛日筛选，起止当天均包含；输入草稿与已生效条件分开；日期仅保留到本标签页整页刷新前，关注列表仍沿用原保存行为。
- **需确认项**：没有阻塞规划的业务歧义。界面采用下文文字方案，尚无已批准视觉稿；编码前按既有界面设计确认约定核对方案，当前规格不代替设计批准。
- **主要风险**：日期被错误地按设备时区换算、非法输入覆盖有效结果、清除日期误清其他筛选，以及重渲染丢失草稿、焦点或最终操作状态。

## Clarifications

### Session 2026-11-10

- Q: 提交日期后，如果用户在结果刷新完成前又开始编辑日期或移到其他控件，刷新结束时应把键盘焦点放在哪里？ → A: 优先保留用户最新主动选择的焦点；没有后续操作时，才回到应用／清除按钮或错误字段。

## 用户场景与测试

### US1：查看指定日期范围的比赛（优先级：P1）

用户填写日期并主动应用，查看所选比赛日内的比赛；输入错误时仍能看到上次有效结果。

**优先级理由**：日期筛选及错误恢复构成本功能的基本用户价值。

**独立验证**：保持阶段为全部、关闭关注筛选，以三个不同比赛日的样例验证日期边界、应用和拒绝错误输入，无需其他故事的组合操作。

#### FR-001：选择并应用日期

赛程页必须提供有明确标签的“开始日期”“结束日期”和“应用日期”按钮，并显示当前已生效日期条件。首次进入时两项为空，摘要为“不限日期”。编辑仅改变草稿；草稿与已生效条件不同时显示“日期尚未应用”，相同时不显示。成功应用须同时更新比赛列表、比赛数量及条件摘要，并清除该次提交前的旧校验错误和未应用提示。刷新等待期间产生的新草稿仍作为未应用编辑保留，不被较早提交的结果覆盖。摘要须区分不限日期、仅开始、仅结束和双端区间。

| 验收编号 | 前置条件 | 操作 | 可观察结果 |
| --- | --- | --- | --- |
| AC-01 | 本标签页首次打开赛程，数据已就绪 | 不填写日期 | 两项为空、摘要为“不限日期”，结果由现有其他筛选决定 |
| AC-02 | 已有一组生效条件 | 修改任一日期但不应用；再改回原值 | 修改期间列表、数量、摘要不变且显示未应用提示；改回后提示消失 |
| AC-03 | 草稿为有效日期条件，提交后未继续编辑 | 激活“应用日期” | 列表与数量对应本次条件，摘要显示生效范围，草稿与生效条件一致，无旧错误或未应用提示 |

**AC-14（日历选择，2026-11-11 用户确认并修订赛事边界）**：开始、结束日期分别提供可键盘激活的日历入口，原文本输入保留。选日仅写入该端 ISO 草稿，关闭并返回入口，另一端、生效摘要、列表和数量保持不变，主动应用后才筛选。单端清空仅改变该端草稿；倒置区间继续由应用校验，不自动交换。Escape、取消和外部点击不改变日期，返回对应入口，外部新操作可随后接管焦点。语言或同页重绘关闭弹层并保留草稿；弹层内焦点恢复到对应入口，后续主动移焦仍优先。离页沿用 FR-006，主题／语言及视口按 AC-11 检查。

| 场景 | 可观察规则 |
| --- | --- |
| 赛事范围 | 以数据就绪后的完整赛事快照中最早、最晚比赛日为闭区间；当前快照为 `2026-06-11` 至 `2026-07-19`，此数值是当前数据事实，不是硬编码配置 |
| 日期可选性 | 首末日及两者之间所有真实日期均可选，包括没有比赛的日期；区间外日期若显示则禁用，不可通过点击或键盘选中，不自动跳过区间内休赛日 |
| 导航 | 仅可浏览与赛事区间相交的月份；上一月／下一月在边界月份禁用，年份／月份快速定位不得越界；方向键、Home／End 到达界外时停在最近的边界日，不让焦点落到禁用日期 |
| 初始定位 | 优先取对应有效草稿，其次有效生效值，最后赛事首日；候选早于首日或晚于末日时，日历光标分别定位首日或末日。仅改变弹层光标，不裁剪、清空或自动应用原草稿 |
| 其他筛选及空结果 | 阶段、关注球队和已应用日期不改变日历上下界；过滤结果为零但完整快照非空时仍可选择赛事区间日期 |
| 空快照与不可用数据 | 数据就绪但完整快照为空时，两个日历入口禁用并提供双语原因说明；不回退到 `0001-01-01` 或系统日期。手写输入、应用和清除仍可用。数据加载／错误沿用 FR-009，不把错误视为空快照 |
| 手写兼容 | 手写仍按 FR-003 校验完整真实公历日期，允许赛事范围外日期；筛选按 FR-002 处理，可得到零场。日历限制不得加入通用日期校验或应用校验 |

验证需覆盖单日赛事快照（首末日相同）、乱序比赛、跨月边界、区间内休赛日、越界草稿打开后取消、空快照，以及切换其他筛选后上下界不变。后续快照重试或更新时，日历使用最新完整快照边界，原草稿和生效值仍不自动改写。

#### FR-002：按快照比赛日进行包含两端的筛选

日期必须按赛事快照中的比赛日期比较，采用 `YYYY-MM-DD` 的年月日含义，不从当前日期、设备时区或比赛时间字符串推算。控件旁显示“按赛事数据中的比赛日期筛选”。输入的可见格式可遵循浏览器本地化。

| 条件 | 匹配规则 |
| --- | --- |
| 两项为空 | 日期不限 |
| 只有开始日期 | 比赛日期大于或等于开始日期 |
| 只有结束日期 | 比赛日期小于或等于结束日期 |
| 两项为同一天 | 仅匹配当天 |
| 开始早于结束 | 包含两端日期的完整区间 |
| 日期有效但部分或全部在赛事范围外 | 按实际区间匹配，允许零场，不自动改为赛事首末日 |

**AC-04**：给定分别发生在 `2026-06-11`、`2026-06-12`、`2026-06-13` 的三场受控比赛：不限定日期得到三场；仅开始为 `2026-06-12` 得到后两场；仅结束为 `2026-06-12` 得到前两场；双端均为 `2026-06-12` 只得到第二场；区间 `2026-06-11` 至 `2026-06-12` 得到前两场；区间 `2026-06-14` 至 `2026-06-15` 得到零场。更换浏览器时区后，每种条件匹配的比赛标识集合不变。样例仅用于验证，不改写正式快照。

#### FR-003：拒绝无效日期并保留有效结果

非空日期必须是完整且真实存在的公历日期，两项都有值时开始不得晚于结束。无效提交须保留输入和上次生效条件、列表、数量，在字段旁显示关联错误；不得交换日期、修正为其他日期或显示为零场结果。输入完整性及日期有效性先于区间先后校验。

**AC-05**：给定已有有效筛选结果，执行下表操作；失败后修改输入并再次应用有效条件，须按 AC-03 成功。失败时草稿与生效条件不同，未应用提示仍显示。表中焦点结果以提交后没有再次主动编辑或移焦为前提；有后续操作时按 FR-007 的优先规则处理。

| 输入与操作 | 错误反馈与焦点 |
| --- | --- |
| 输入 `2026-06-13` 至 `2026-06-11` 并应用 | 结束日期旁显示“结束日期不能早于开始日期”，聚焦结束日期 |
| 输入非空但不完整的日期，或不存在的 `2026-02-30` 并应用 | 对无效字段显示“请输入有效日期”，聚焦阅读顺序中的第一个无效字段 |
| 两项均有日期有效性错误并应用 | 两个错误各自关联字段，焦点落在开始日期 |
| 输入有效闰日 `2024-02-29` 并应用 | 通过日期校验；是否有比赛按 FR-002 判断，不因年份不同而拒绝 |

### US2：组合筛选并快速恢复结果（优先级：P2）

用户在所选日期内筛选阶段和关注球队，或一次操作移除日期限制而保留其他选择。

**优先级理由**：支持已有筛选的组合使用，避免用户清除日期后重选其他条件。

**独立验证**：以给定的生效日期和关注列表为前置，单独核对交集、去重、清除和空态；不需要语言切换或页面往返场景。

#### FR-004：日期、阶段与关注条件取交集

结果必须同时满足已生效日期、当前赛事阶段及“只看关注球队”的条件。阶段、关注开关或关注列表变化时，必须使用已生效日期重新计算，不自动应用日期草稿。双方都被关注的比赛只显示一次，数量按不同比赛计算。结果保留现有阶段分组、小组字母分组及各组内原有顺序。

**AC-06**：给定四类比赛：①区间内且满足其他条件；②区间外但满足其他条件；③区间内但阶段不匹配；④区间内但不涉及关注球队。应用三个条件后只显示①；①的双方都被关注时，卡片及计数不重复。保持未应用日期草稿，切换阶段或关注开关后，草稿与生效摘要各自不变。已生效区间跨页面关注操作后仍有效，离页时的草稿处理遵循 FR-006。

#### FR-005：单独清除日期并区分空态

数据就绪的日期控件区始终提供可操作的“清除日期”按钮。一次激活必须清空两项输入、生效日期、错误和未应用提示，立即重算结果；保留阶段、关注开关及关注列表。不限日期时再次清除，状态不变。合法零结果不得渲染空的比赛分组，日期控件与清除入口仍可使用。

| 验收编号 | 前置条件 | 操作 | 可观察结果 |
| --- | --- | --- | --- |
| AC-07 | 日期、阶段和关注筛选均生效，或日期输入有错误 | 激活“清除日期”；再次激活 | 首次后结果等于仅应用后两个条件，摘要为“不限日期”，输入和提示已清空；第二次无状态变化，其他选择均保留 |
| AC-08 | 合法组合得到零场比赛 | 查看反馈并尝试调整或清除日期 | 数量为零且无空分组；开启关注筛选但未关注球队时提示尚未关注并提供选择球队入口，其余情况显示“当前筛选条件下没有比赛”；清除入口可用，不承诺清除后必有比赛 |

### US3：切换语言和页面后继续浏览（优先级：P2）

用户使用中英文、不同主题和键盘浏览时，可以继续操作日期筛选，并明确哪些状态会保留。

**优先级理由**：与已有语言、主题、导航能力兼容，并保障键盘操作可完成主流程。

**独立验证**：分别准备有效筛选、未应用编辑和输入错误状态，单独验证语言／主题切换、页面往返、刷新、键盘操作与布局。

#### FR-006：明确状态保留边界

日期条件仅属于当前标签页的一次页面会话，状态按下表处理；不新增持久化记录、分享参数或跨标签页同步。日期生命周期不得改变已有关注列表的保存结果。所有新增标签、说明、摘要、按钮、未应用提示与错误必须有含义一致的中英文版本；语言切换不得留下上一语言的应用文案。

| 事件 | 已生效日期 | 输入草稿与校验状态 |
| --- | --- | --- |
| 切换语言、主题或在赛程内调整其他筛选 | 保留 | 保留输入及错误状态；文字随语言更新 |
| 离开赛程页，再在同一标签页返回 | 保留 | 放弃未应用编辑，输入恢复为生效值，旧校验错误和未应用提示清除 |
| 整页刷新或新开标签页 | 恢复不限日期 | 两项为空，无校验错误或未应用提示 |

**AC-09**：分别从有效筛选、未应用编辑、输入错误三种状态切换语言和主题，结果及状态符合表格；目标语言覆盖全部新增文案。进入比赛详情后返回，及离页去球队页改变关注列表后返回，均保留生效日期且重新计算结果；未应用编辑已放弃。整页刷新和新开标签页后日期为空，已有持久化关注记录仍可正常恢复。

#### FR-007：支持键盘操作、焦点与连续反馈

两项输入、对应日历入口和应用／清除按钮必须有可访问名称，按阅读顺序可用键盘到达并激活。用户在应用或清除后的刷新等待期间继续编辑日期，或主动移到其他控件时，刷新后须优先保留其最新主动选择的焦点，不因较早操作把焦点抢回按钮或错误字段。

没有后续主动编辑或移焦时，成功应用后焦点留在应用按钮，清除后留在清除按钮，输入错误按 FR-003 聚焦。若最新选择的目标因结果变化已不存在或无法操作，则回到本次操作的上述默认目标，不落回页面根部。日期操作不得强制滚动至页顶。数量更新须可被辅助技术感知。由语言切换控件发起切换后，若没有新的主动移焦，焦点留在该控件，不抢到日期区。连续操作以最后一次有效操作为准，旧操作不得覆盖较新结果或重复触发。

**AC-10**：仅用键盘完成输入、应用、修正错误和清除，逐步核对上述焦点与数量反馈。连续应用两个有效区间、应用后立即清除，以及快速切换阶段／关注条件后，最终结果与最后有效状态一致，焦点不落回页面根部。最后一次日期提交无效时，仍使用最近一次有效日期并保留错误反馈。

另在刷新尚未完成时验证焦点优先级：

| 后续操作 | 刷新完成后的预期 |
| --- | --- |
| 应用后回到日期输入继续编辑 | 焦点留在正在编辑的字段，新草稿及未应用提示保留；结果仍使用最近一次成功提交的日期 |
| 应用、清除或无效提交后主动移到另一个仍可用的控件 | 焦点留在最新选择的控件，包括赛程内控件或语言按钮，不被旧操作抢回 |
| 没有后续主动操作 | 按本次操作的默认规则聚焦应用按钮、清除按钮或首个错误字段 |
| 最新选择的控件因结果变化不再存在或不可操作 | 回到本次操作的默认目标，焦点不落回页面根部 |


#### FR-008：沿用现有视觉风格并适配窄屏

日期区域必须位于现有筛选区内、比赛列表之前，阅读顺序为开始日期输入及日历入口、结束日期输入及日历入口、应用日期、清除日期。日期口径说明、条件摘要和字段错误邻近对应控件。按钮、输入、提示及深浅主题沿用项目现有风格，比赛卡片、球队徽标及阶段标签保持现有呈现。窄屏允许换行，不遮挡文字、不重叠、不因新增区域引起页面横向滚动；焦点指示须可见。

**AC-11**：在 `1440×900`、`390×844` CSS 像素视口及 100% 缩放下，检查中英文与深浅主题的全部八种组合。在各组合中检查默认、生效、未应用、错误、空结果状态，均满足以上布局与可读性要求；实际运行证据和交互结果由后续验证记录，规格不预填通过。

### 边界情况

日期空值、单端、同日、区间外按 FR-002；非法日历日期及倒置区间按 FR-003；双方关注去重按 FR-004；清除后仍为零场按 FR-005；同页重绘与真正离页按 FR-006；快速操作与无效末次提交按 FR-007。数据未就绪、失败与重试按 FR-009。以上为各边界的唯一需求定义，不另设重复用例。

## 需求

### 功能需求

FR-001—FR-003 对应 US1，FR-004—FR-005 对应 US2，FR-006—FR-008 对应 US3；定义及验收紧邻各故事正文。以下 FR-009 为三个故事共用的可用性要求。

#### FR-009：区分数据可用状态并保持核心浏览独立

首次数据未就绪时使用现有加载反馈，不展示可提交的日期控件；数据加载失败时显示现有错误和重试入口，不展示为零场比赛。重试成功后以会话内最后有效日期和当前其他条件恢复结果。数据已加载后的日期操作不新增网络请求或独立加载状态。使用既有静态快照并保留非实时、非官方说明；日期筛选不依赖 AI 服务。

- **AC-12**：给定首次加载尚未完成，用户不能提交日期；给定数据加载失败，显示数据错误和重试入口，不能误认为无比赛；给定此前有生效日期，重试成功后的结果满足原有效日期及当前其他条件。
- **AC-13**：给定赛事数据已加载，在 AI 服务未配置或不可用时，应用／清除日期、查看结果及进入比赛详情均可用；日期操作不额外请求赛事或 AI 数据，静态快照说明仍可见。

### 关键实体

- **比赛**：以既有唯一标识识别，包含比赛日期、阶段／轮次、小组和对阵球队；本功能读取这些信息，不改变快照内容或引用关系。
- **日期草稿**：用户正在编辑的开始、结束日期，允许为空或暂时无效；仅在有效应用后成为生效条件。
- **已生效日期条件**：最近一次成功应用的可选开始、结束日期，用于结果筛选与摘要；与草稿分别保留。
- **组合筛选状态**：生效日期与已有阶段、关注开关、关注列表共同决定结果；清除日期只改变日期部分。
- **校验反馈**：字段错误与焦点目标，和“尚未应用”状态共同解释草稿尚未影响结果的原因。

### 兼容性与数据边界
