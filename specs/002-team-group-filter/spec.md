# Feature Specification: 球队分组筛选

**Feature Branch**: `002-team-group-filter`

**Created**: 2026-10-21

**Status**: Draft

**Input**: `requirements/task-2.md`：「在球队页面，用户可以选择只显示其中某一个或某几个分组的球队信息。」

**Feature Directory**: `specs/002-team-group-filter`

## Clarifications

### Session 2026-10-21

- Q: 用户取消最后一个已选小组后，应该显示什么？ → A: 恢复显示全部球队；没有选中小组表示不限制分组。
- Q: 用户离开球队页再返回，或刷新页面后，是否保留之前选择的小组？ → A: 同一标签页未刷新时，离开后返回保留选择；刷新后恢复显示全部。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只看所选小组的球队 (Priority: P1)

作为浏览球队的用户，我希望选择一个或多个小组，只查看这些小组的球队，并能随时恢复查看全部球队。

**Why this priority**: 这是本次需求的核心，减少浏览无关球队的操作。

**Independent Test**: 打开球队页，依次选择 A 组、增加 C 组、取消 A 组、恢复全部，核对各步显示的球队。

**Acceptance Scenarios**:

1. **US1-AS1** — **Given** 用户首次打开球队页且数据可用，**When** 页面显示完成，**Then** 默认显示全部球队，提供实际存在的小组选项，清楚表明当前显示全部。
2. **US1-AS2** — **Given** 当前显示全部，**When** 选择 A 组，**Then** 只显示 A 组的全部球队，其他小组标题和球队均不显示，A 组选中状态可辨认。
3. **US1-AS3** — **Given** 已选择 A 组，**When** 再选择 C 组，**Then** 同时显示 A、C 两组的全部球队，每队只出现一次；取消 A 组后只显示 C 组。
4. **US1-AS4** — **Given** 已选择一个或多个小组，**When** 使用“显示全部”操作或取消最后一个所选小组，**Then** 清除分组限制并显示全部球队；再次使用“显示全部”结果相同。
5. **US1-AS5** — **Given** 已选择 A、C 两组，**When** 打开其中一支球队的详情，再在同一标签页未刷新的情况下返回球队页，**Then** 详情属于所点球队，返回后仍只显示 A、C 两组；刷新球队页后恢复显示全部。
6. **US1-AS6** — **Given** 球队页已打开，**When** 仅用键盘选择、取消小组并恢复全部，**Then** 能完成与鼠标相同的筛选操作，操作焦点可见且更新结果后仍可继续操作当前控件。

### User Story 2 - 中英文切换后继续查看相同球队 (Priority: P2)

作为使用中文或英文的用户，我希望筛选提示与当前语言一致，切换语言后仍查看刚才选择的小组。

**Why this priority**: 遵循现有双语体验，避免翻译切换改变筛选含义。

**Independent Test**: 在中文界面选择 A、C 两组，切换英文再切回中文，分别核对实际界面语言、选中小组和球队集合。

**Acceptance Scenarios**:

1. **US2-AS1** — **Given** 中文界面已选择 A、C 两组，**When** 切换到英文，**Then** 筛选标签、恢复全部操作和球队名称使用现有英文展示规则，A、C 组选中状态及球队集合不变；切回中文也保持相同结果。
2. **US2-AS2** — **Given** 当前显示全部，**When** 在中文与英文间切换，**Then** 始终显示全部球队，新增提示使用当前语言，不显示未翻译的内部词条名称。

### Edge Cases

- **EC-01（快速切换）**：**Given** 数据已显示，**When** 连续选择和取消多个小组，**Then** 最终列表与最后的选中集合一致，不残留已取消的小组；全部取消时恢复全部。
- **EC-02（全选）**：**Given** 数据包含多个小组，**When** 逐一选中全部可选小组，**Then** 显示这些小组的全部球队，无重复记录，仍能使用“显示全部”清除选择。
- **EC-03（没有可显示数据）**：**Given** 当前未取得可显示的球队数据，**When** 打开球队页，**Then** 显示“暂无可显示的球队，可刷新重试”的对应语言提示，不生成虚构的小组选项，也不把该状态描述成“所选小组没有球队”。
- **EC-04（个别球队缺少分组）**：**Given** 可用球队中有分组缺失的记录，**When** 显示全部，**Then** 该球队仍可见并标明“分组未知”；选择具体小组时该球队不混入结果，也不把“分组未知”作为可选小组。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 球队页首次打开时必须显示全部球队；可选小组来自当前可用球队数据中有明确分组的记录，按小组字母顺序展示。
- **FR-002**: 用户必须能独立选择或取消一个或多个小组。选中集合非空时，结果为这些小组球队的并集；不得遗漏匹配球队、混入其他组或重复显示球队。选中状态必须清楚可辨。
- **FR-003**: 必须提供一次操作即可恢复全部的入口；无所选小组表示不限制分组，取消最后一个选择也恢复全部。
- **FR-004**: 筛选后必须保留小组分区和字母顺序、组内原有球队顺序及球队卡片信息，用户仍能打开正确的球队详情；隐藏没有入选的小组分区。
- **FR-005**: 新增标签和提示必须提供中文与英文；切换语言必须保留选中小组集合及对应球队结果，不改变筛选含义。
- **FR-006**: 同一标签页未刷新时，离开球队页后返回必须保留选择；刷新或新打开页面时恢复显示全部。选择仅影响球队页。
- **FR-007**: 分组选择、取消和恢复全部必须可通过键盘完成；控件具有可理解的名称、可辨认的选择状态和可见焦点，更新结果后可继续操作当前控件。
- **FR-008**: 当前没有可显示的球队数据时，必须呈现中性的无数据可用提示和刷新重试指引，不生成虚构的小组选项，不声称这是筛选无匹配结果。
- **FR-009**: 分组缺失的球队必须在“显示全部”中以“分组未知”呈现，并排除在具体小组的筛选结果和可选小组之外。

### Key Entities *(include if feature involves data)*

- **球队**：已有的球队标识、名称、分组及卡片信息；本功能只改变哪些球队可见。
- **小组**：球队已有的分组字母；有明确分组的球队共同形成可选小组集合。
- **分组选择**：当前所选的小组集合；空集合代表显示全部，不构成长期用户偏好。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对单组、多组、取消部分、全选和恢复全部的验收场景，显示的球队集合与预期完全一致，遗漏、混入和重复数量均为 0。
- **SC-002**: 球队数据已显示的情况下，选择或取消小组后 1 秒内完成可见结果更新；恢复全部只需一次操作，无需手动刷新。
- **SC-003**: 中英文切换、详情往返、刷新和键盘操作场景全部符合本规格的状态规则，新增用户文案均可读且与当前语言一致。

## Assumptions

- 已确认：无选择代表全部，取消最后一个所选小组后恢复全部；同一标签页未刷新时，离开后返回保留选择，刷新后恢复全部。其余默认补充：多选按并集处理；语言切换保留选择；新打开页面显示全部。
- 本轮用于轻量级 SDD 演示。后续 `tasks.md` 的任务总数不得超过 **20 个**，包含真实 TDD、必要回归和验收；任务上限不能用来省略已启用的质量规则。
- 范围限于球队页分组筛选，使用现有赛事快照及球队详情入口。账户、跨设备同步、长期保存筛选、链接分享筛选、搜索排序组合、赛事数据更新均不纳入本轮。
- 不新增筛选链接参数，直接访问球队页按 FR-001 处理；缺失或非法筛选参数不构成本功能入口。
- 数据已取得但未包含的球队无法由本功能补齐；不推断该队未参赛。整体数据加载、重试机制的重构不在本轮范围，EC-03 只要求明确当前没有可显示数据。

### 赛事数据语义与范围

- 数据来源及适用快照：使用基线提交中的现有 2026 世界杯球队静态快照，服务学习与功能演示，不宣称实时或官方赛事状态。
- 本功能数据范围：球队及其所属小组；不涉及比赛比分、积分、排名计算或赛事数据修订。
- 展示语义：小组按字母顺序，组内延续原有顺序；选中多组表示并集，球队以既有标识区分。
- 完整性语义：无选择是全部；没有可用数据按 EC-03；个别分组缺失按 EC-04；不以缺少记录推断未参赛，也不宣称补齐未提供数据。
- 用户可见时效说明：沿用现有快照说明，不新增“实时更新”或“官方完整名单”承诺。
