# 数据模型：球队分组筛选

## 既有球队

沿用 `public/data/teams.json`：以球队 code 为唯一键，记录包含 code、name、group、confederation、ranking 等既有字段。不改文件格式、不写回数据。组内顺序按现有 Object.values 输入顺序；不会因选择顺序或语言改变。

## TeamGroup

| 字段 | 含义与约束 |
| --- | --- |
| key | 有明确分组时为原分组字母；分组缺失时使用内部空字符串哨兵，不作为可选项 |
| teams | 属于本组的球队，保留原顺序；输入为以 code 唯一标识的既有球队字典 |
| visible | selectedGroups 为空或包含本组 key；未知组仅在 selectedGroups 为空时可见 |

可选组来自全部当前可用球队，而非过滤后的结果，按字母排序，因此选择 A 后仍能选择 C。未知组排在已知组后面，标签由当前语言生成。null、undefined、空字符串和纯空白分组归为未知；不在本轮推断缺失的真实分组。

## GroupFilterState

| 字段 | 规则 |
| --- | --- |
| availableGroups | 当前数据生成的有效小组集合；不含未知哨兵 |
| selectedGroups | availableGroups 的子集，去重；空集合表示全部 |

拟提供 `createGroupFilterState()` 便于单测隔离，并导出应用共享实例。读取返回副本，避免调用方直接篡改内部集合。

| 事件 | 状态转移 | 用户结果 |
| --- | --- | --- |
| 初始化/刷新/新页面 | selectedGroups = 空 | 全部 |
| 同步可用小组 | 保留仍有效的选择，去除已不存在的组 | 选择不变或退回全部 |
| 设置某组 checked | 添加或删除该组；未知组请求不生效 | 显示已选组并集 |
| 取消最后一组 | 空集合 | 全部 |
| 显示全部 | 清空；重复执行不改变结果 | 全部 |
| 离开再返回 | 保留内存实例 | 恢复已有选择 |
| 中英文切换 | 选择不变 | 相同球队集合，新语言 |

状态只归属于当前文档，不使用持久化存储、不编码到 URL、不影响关注球队或赛程筛选。原生 change 使用目标 checked 值，不依据可能过期的复选框集合重算选择。

## 纯逻辑边界

`src/features/team-group-filter/state.js` 拟包含构建分组、分组可见性判断和状态创建。视图与控制器必须调用相同的可见性判断，不能各自维护两套筛选语义。计算规模为 O(球队数 + 小组数)，无外部服务依赖。
