# WorldCup2026 项目宪法

## 核心原则

### I. 赛事数据契约与来源一致

赛事展示与 AI 数据查询必须遵循同一套已确认的数据语义。修改赛事数据、共享查询逻辑或双语词典时，必须检查标识唯一性、跨实体引用和受影响内容的一致性，并记录检查结果与未解决问题。静态快照、演示数据与实时或官方信息的边界必须明确；未经需求确认，不得将静态数据描述为实时或官方结果。

### II. 核心赛事浏览独立于可选 AI

核心赛事浏览必须保持独立于外部模型服务和 AI 密钥配置。涉及 AI 接入、初始化或故障处理的变更，必须明确不可用时的用户反馈及对核心浏览的影响，并提供相应验收依据。AI 的失败不得阻断核心赛事浏览。

### III. 双语与跨设备体验保持一致

面向用户的功能变更必须检查中文、英文和移动端布局中的对应行为，保持信息含义与关键操作一致。兼容性验收必须声明实际检查的浏览器、版本和设备范围；未检查的范围必须明确记录，不得以单一浏览器结果推断全部兼容。

## 项目约束与适用范围

本宪法适用于 WorldCup2026 的需求、设计、实现和评审。项目补充原则承接已批准的项目方向；具体框架、依赖版本、部署参数和操作命令由对应设计及维护文档记录，不因现有实现而自动成为永久约束。

浏览器范围沿用已评审建议：当前稳定版 Chrome、Edge、Firefox、Safari，以及 Android Chrome、iOS Safari；具体最低支持版本继续由后续兼容性评审确定，本宪法不自行填写版本下限。

工程规则以本次有效规则快照为唯一来源。模板示例、历史注释、已有脚本及其他框架受管区段不得新增或覆盖工程门槛。本次未启用增量覆盖率 HTML 和需求 TDD HTML 报告要求，仓库存在相关命令不构成强制报告义务。

## 开发流程与遵循检查

需求必须区分已确认期望、现状事实与待确认事项，并提供可检查的验收条件。设计与任务应将适用宪法条款映射到具体变更及验证方式。

计划在研究前及设计完成后逐项进行宪法检查；交付评审再次逐项记录符合、不适用或存在差距及其依据。可单测行为的变更按受保护规则保留真实失败、最小实现通过及必要回归的执行证据；覆盖率使用本功能明确基线和新增自有生产代码范围计算，不得直接沿用不适用的历史功能基线。

未执行、执行受阻或证据不足的检查必须如实记录。宪法条款表达应达到的要求，不代表当前实现已经符合。历史缺陷应另行评估，不得直接转写为强制设计。

## 治理

本宪法是本项目 Spec Kit 工作流的治理依据。项目约定及模板使用必须与本次有效工程规则一致；受保护区段中的启用条款不得通过项目补充、例外或历史政策降低、删除。

修订必须提交变更内容、理由、影响范围、版本变化及必要迁移说明，由用户评审批准后生效。尚未批准的政策建议保持候选状态；遵循检查不能自行批准政策变更。

版本采用语义化版本：删除或重新定义原则、引入不兼容治理变化时升级主版本；新增原则或实质扩展约束时升级次版本；不改变义务的澄清和文字修正升级修订版本。

本候选暂按已批准决定使用首次批准版本 1.0.0：当前未读到已有宪法，不能宣称这是对已知历史版本的升级。应用前若发现真实历史宪法，必须保留其真实批准日期、核对仍有效的信息，并重新评估版本迁移；与本次快照冲突的历史规则应显式提出修订，不得静默继承。首次批准和本次修订日期由向导在用户确认宪法评审时填写。
