## 项目任务格式与路径

每条任务在官方 ID、可选 [P] 和 [USn] 后增加一种类型标签：[测试]、[实现]、[验证]、[准备] 或 [文档]。人工执行者标签 [人工] 按条件追加，不替代类型标签。[P] 只用于文件无冲突且依赖满足的任务。

格式示意，仅在生成具体任务时分配真实编号和内容：

```text
- [ ] T010 [P] [US1] [测试] [层级、目标行为、真实生产入口、关键断言及测试文件]
- [ ] T011 [US1] [实现] [代码范围、文件路径和可检查成果]
- [ ] T012 [US1] [验证] [实际命令或可观察结果及关联验收]
```

路径按 plan.md 的实际变更地图选择：生产代码 src/、netlify/functions/；静态数据与词典 public/data/、public/i18n/；Vitest 测试 tests/、Playwright 测试 e2e/。不照搬 Python、通用 backend/frontend 或其他项目示例目录。

## 按用户故事生成任务

每个故事只输出有适用任务的分组，顺序为“测试任务（先行）”“实施任务”“验证任务”。本次启用真实 TDD：新增或修改可单测行为及缺陷修复，测试先实际运行并因目标行为未实现而失败，再进行对应最小实现；不要额外建立 Red/Green 收据。纯重构先跑现有测试，纯视觉或配置采用适用验证；不适用测试先行时说明原因及替代方式，不能因基础示例写着测试可选而省略启用要求。

- [测试]：写明单元／集成／契约／端到端层级、目标行为、真实被测生产入口、关键断言与文件；替身隔离外部依赖，不替换核心逻辑。
- [实现]：按可检查成果描述受影响代码与兼容处理，不罗列普通编码动作。
- [验证]：写实际命令或可观察结果。Vitest 可用 npm test -- <实际测试路径>；端到端按构建和预览前置使用 npm run test:e2e -- <实际测试路径>；数据、构建及覆盖率按计划选择既有命令。覆盖率引用 plan.md 的独立比较基线、范围、80% 门槛和显式输出命令，不复制历史固定功能基线。
- [准备]：仅为已识别阻塞准备环境、数据或必要验证能力；配置存在不代表能力完成，不新增 CI 接入任务。
- [文档]：仅更新本次变更实际影响的原生需求、计划、契约或使用说明。

共享准备只在确实阻塞多个故事时集中安排。测试与验证靠近所属故事，不统一挪到末尾，不另建重复任务汇总表，不为凑章节生成任务。实际测试命令和结果在对话或现有 PR 简述，任务只保留必要完成状态、阻塞与交接。

### UI 故事的依赖安排（仅 UI 功能）

沿用 spec.md 的识别、模式与基线，以及 plan.md 的组件映射。非 UI 不增加设计或截图任务；待确认先澄清。轻量模式在原有工件安排局部实现与对应验证，不生成完整附加文档。

完整模式按依赖安排：必要最小业务数据准备 → 结构与主要控件 → 当前界面实际运行与截图 → 对照已确认基线 → 修正重要偏差 → 剩余业务逻辑 → 交互及适用视觉回归。各任务仍归所属故事与上述适用分组；用显式依赖表达次序，测试先行约束继续适用，不能把全部测试拖到视觉检查之后。

初步运行使用的模拟状态写明，不能代替最终集成验证。运行入口沿用 plan.md：前端开发／预览、/?mock 演示和真实 Function 环境分别验证。截图引用当前候选及运行环境，需求图片、旧截图或构建成功不作为当前运行结果；必要差异表记录在已有验证位置。不能运行或看图时保持待验证并说明下一步。

偏差按原因处理：需求不完整或冲突先澄清；方案不适用修订设计与任务；实现偏离仅修相关代码和测试；设计变化先重新确认并分析影响。保留有效任务 ID、代码和决定，仅重新打开受影响项；基线或实现改变后重新核验旧截图及通过结论，不重新生成整个功能，不改正确需求迁就错误实现。文档修订不自动授权实施。

### 必要人工交接与批次执行

先读取宪法及其引用的验收、审批和发布约定，再核对本功能验收场景。默认不增加最终人工验收；已有人工任务覆盖时不重复。自动化受当前设备、数据或权限限制仍标为自动化并写“阻塞原因”，不将失败或缺失实现转成人工任务。

需要混合任务或显式依赖时，在原任务文档输出 <!-- repo-sdd:hybrid-tasks:v1 -->；明确停用时输出 <!-- repo-sdd:hybrid-tasks:v1 {"enabled":false} --> 并执行原生规则。无执行者标签沿用 Agent；依赖以缩进说明“依赖：T010, T011”。无人工项不输出空分组。

必要人工项在原任务下写负责人、环境、原因、步骤、预期、证据和“发布必需：是／否”，默认发布必需；仅正式签收写“最终验收：是”。通过由授权人员填写执行人、执行日期（YYYY-MM-DD）、实际环境、结果：通过及结果证据后勾选，Agent 不代写或代勾。失败保持未勾选，记录结果：失败、问题编号、复现步骤和证据；修复任务以“关联任务”引用原项。延期按已有流程批准，记录发布必需：否、延期批准人、延期截止日期和延期原因，保留待验收状态。

执行前读取整份清单并说明本轮范围；未指定批次时沿用当前授权，内部按依赖推进，不新增逐批人工审批。仅获准某批时完成后停止。原生 tasks.md 是唯一任务清单，不另建批次状态文件。

从当前 Spec Kit 项目指南定位运行组件及规则快照，使用 workflow/run.ps1 inspect-tasks --tasks <仓库相对路径>，或同目录 python -B runtime.py inspect-tasks --project . --rules <当前规则快照> --tasks <仓库相对路径>。入口不可用先记录能力缺口，不能猜测或恢复历史已删除路径。可用 --story、--phase、可重复 --task-id 限制范围；无选择检查全部，重复任务 ID 取并集，不同选择参数取交集。同名阶段以明确 ID 消歧；依赖检查整份清单，范围外前置未完成即阻塞，不扩大授权。空匹配、未知或重复 ID、非法或循环依赖先处理，不回退执行全部。

检查器技术输出需核对 result_version: 2、selected_tasks、batch_remaining_ai、batch_pending_manual、ready_ai 和 blocked。batch_status 为 invalid 先修输入，ready 仅推进获准 ready_ai，blocked 说明前置缺口，pending_manual 说明仍待人工，complete 仅表示所选任务记录完成。每完成 Agent 任务更新原生复选框并重算，人工框保持原样；无关人工项不阻碍独立 Agent 工作。

区分 batch_ai_complete、execution_batch_complete 与全局 implementation_complete／pending_manual；退出码 0 只表示检查成功，verification: unverified 不被勾选或批次完成改成测试、覆盖率或 CI 已通过。无混合标记旧清单保留原生语义，不从自由文本推断人工或延期授权；确需人工但标记不明时澄清。

批次结束在对话列出范围、已完成与剩余 Agent 任务数、待人工项、阻塞及原因、真实自动测试结果、可交接范围和下一步。最终按原生流程复核实现差距与真实测试，仅完成实际核对后在适当原任务记录“实施复核：通过”和检查器返回的“复核修订”；正式人工验收由授权人员填写。当前修订记录齐备后才报告已收尾，需求变化使结论失效时保留历史并重新打开受影响项。

完整功能的 converge 仍作全量差距检查与必要追加，不强制每批调用；不得将未获准实施的下一批计划任务重复作为缺陷。正式 Bug 请求沿用 speckit-bug-assess → speckit-bug-fix → speckit-bug-test 的阶段授权与官方产物，不自动串行推进。
