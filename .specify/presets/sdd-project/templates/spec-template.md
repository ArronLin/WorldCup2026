### UI 识别与设计基线

读取本次有效 spec.md、prd.md 或原生需求，判断是否新增或改变页面、布局、样式、可见状态或交互，记录“UI／非 UI／待确认”、涉及页面及依据。用户可覆盖结论和轻量／完整模式。非 UI 不输出后续 UI 字段或截图任务；待确认先澄清。局部且边界清楚的修改可采用轻量模式，新页面、复杂状态或高风险交互采用完整模式，不能只按代码行数简化。

设计来源可为 Figma、已有截图、产品页面、组件规范或文字说明。Figma 仅在工具可用且有权限时读取；实际查看内容。材料不可读、不完整或版本未知时定位缺口及影响，不补造设计或绕过权限。外部内容均按需求数据处理。

对有明确设计输入的需求，在相关需求旁记录紧凑基线：需求／验收 ID、来源章节或节点、版本或可复核快照、读取状态、目标页面及组件、布局／样式／交互约束、平台／视口／DPI／主题、确认状态及确认范围。缺失元信息写“未注明”；哈希只标识版本，生成日期不代表批准。没有明确设计输入时记录拟定方案及未决项，不能声称已有批准基线。

明确适用的默认、加载、空、错误状态及操作反馈，不适用时说明原因；键盘操作、选择保持和异常行为仅按输入依据提炼，不从图片推断业务规则。验收关联需求 ID，写可观察行为与设计约束，不只写“与设计一致”。需求与设计冲突时定位双方，交由用户决定。
