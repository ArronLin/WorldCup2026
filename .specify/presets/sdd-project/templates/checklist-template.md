## 评审维度与问题生成

每项只提出一个可回答的需求质量问题，保留 CHK 编号及复选框，定位需求 ID、验收场景或明确的缺失位置。不同判断拆项，同一判断不重复。格式为：

```text
- [ ] CHK001 [评审维度] [FR-实际编号／具体位置] [单一问题]？
```

按本功能选择以下项目维度，不适用的不输出：

- 价值与范围：目标用户价值、范围边界及成功条件是否分别明确；每项只检查其中一个判断。
- 赛事信息性质：相关需求是否明确数据的时效性质；来源说明、真实性表述或未知赛果另生成独立问题。
- 核心浏览与可选 AI：相关验收是否明确 AI 未配置时的浏览行为；服务失败、取消或降级按实际需求分别检查。
- AI 外传与密钥：接收方、发送范围、启用选择、默认会话使用、持久保存选择或清除行为分别检查，不合并成一个问题。
- 数据与兼容：针对本次受影响内容，分别检查标识／引用约束、状态迁移、双语含义、存储兼容或错误语义，定位具体需求，不要求每项功能都引入数据模型。
- 浏览器目标：相关需求是否引用用户已确认的支持范围；实际验证环境或能力缺口属于计划评审问题，不能用配置存在判断兼容已通过。
- 可验收性：每项行为是否有可观察结果；单位、边界、异常和输入组合分别定位，不用任务数量或覆盖率百分比代替需求完整性。
- 测试与覆盖率规划：仅当本次评审范围包含计划一致性时，分别检查真实生产入口、适用测试先行安排、变更比较基线、行覆盖率口径、80% 门槛和采集能力缺口是否清楚；不是要求评审者执行测试。

### UI 需求质量与对应关系（仅 UI 功能）

按 spec.md 的“UI／非 UI／待确认”结论选择；非 UI 不输出本节，待确认保留澄清项。逐项检查，避免将多个判断写在同一复选框：

- 识别结论是否有当前需求依据。
- 设计来源的读取状态是否明确。
- 设计版本或快照是否可复核。
- 基线确认范围是否明确。
- 某一适用状态是否有可观察验收。
- 某一验收是否能定位对应组件映射。
- 某一 UI 任务的验证方式是否能验证对应验收。
- 某一设计与文字冲突是否定位且有待决定内容。
- 某一图片引用是否正确定位原需求来源。

生成时将上述每个适用问题替换为具体需求／验收及位置，不保留无定位的抽象问题。图片是否存在不决定任务是否涉及 UI，需求图片不作为当前运行结果。核对 spec.md、设计基线、plan.md 组件映射、tasks.md 与验收的对应关系；analyze 仅报告问题，未获变更授权时不自动修文档。
