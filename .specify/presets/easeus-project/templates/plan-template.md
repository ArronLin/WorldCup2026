### 交互与产物语言
所有面向人的自然语言内容，包括标题、小标题、表头、任务类别、状态说明、目标、依赖与验证文字，使用简体中文；命令、文件路径、API 与代码标识符、协议关键字和框架固定标记保持原样。引用必须保留的英文固定标记时，应在相邻位置提供简体中文说明；不得照抄基础模板的英文标题作为最终文档标题。

### 真实 TDD
新增或修改可单测行为及修复缺陷时，先编写测试并实际运行，确认测试因预期行为尚未实现而失败，再编写最小实现使测试通过，随后按需重构并回归验证。依赖、环境或语法错误不能作为有效的 Red；不得将事后补写测试宣称为 TDD。

### 可计量新增业务逻辑测试覆盖率
对仓库现有工具能够可靠采集的新增或修改自有生产代码可执行业务逻辑，单元测试覆盖率不低于 80%；优先采用语句或分支覆盖率，现有工具仅提供行覆盖率时可使用行覆盖率。纯声明式界面（包括 QML）、生成代码、资源和配置不纳入百分比分母，但相关属性、绑定、信号、状态变化及关键用户场景必须通过自动化行为测试；复杂业务逻辑应优先移入可单测模块。无可靠采集能力时明确记为不适用或能力缺口，不得填成 0% 或 100%，也不得用 qmlprofiler 等性能分析事件作为覆盖率证明。

### 有效测试与验证
测试必须调用真实被测生产逻辑，包含能识别错误行为的断言并实际发现和执行。禁止占位成功、恒真断言、mock 掉被测核心与静默跳过；未实际执行测试不得宣称通过。关键控制逻辑采用可恢复的反向验证或适用变异测试。

### 来源与事实核实
知识库与源码说明现状，已确认需求定义期望；关键结论记录来源与适用版本，未知必须明确，现状缺陷不得自动固化为规范。
正文开头增加“评审摘要”，依次展示方案摘要、变更地图、关键决策、需确认项和风险。决策说明选项、选择理由和影响；正文按组件与依赖展开，来源和技术细节后置。
派生文档同样采用评审优先结构：research.md 只记录决策、备选方案与依据；data-model.md 聚焦实体、约束、状态与迁移；contracts/ 聚焦接口、兼容与错误语义；quickstart.md 只给最短验证路径、预期结果和排障。不得复制背景或保存原始日志。
记录来源、适用版本、关键差距与待决定事项。保持该阶段原有职责，不将未执行验证标为通过。

- 覆盖率：[可靠可计量的新增或修改自有生产业务逻辑范围、排除项、现有工具口径与适用比较基准；门槛按 effective_policy，本次为 80%]

可单测行为按有效规则先写测试并实际确认预期行为失败，再实施和回归；环境、依赖及语法错误不算有效失败。纯声明式界面、生成代码、资源和配置不进入覆盖率百分比分母，相关行为仍安排自动化验证。无可靠采集能力时写明“不适用”或“能力缺口”，不填写虚假百分比。

复用 npm run test:coverage、npm run coverage:added 等现有入口前，核对其参数、比较基准及变更范围。已有脚本按可执行语句起始行汇总，不能称为完整分支覆盖率；不得将旧故事专用比较基准固定用于所有变更。所需能力不足时，在计划中明确建设工作并交由 tasks.md 安排；配置存在不代表能力已验证。不新增 CI 接入任务。

## 派生设计文档的项目字段

- research.md：仅记录决策、备选及依据；需确认项与风险前置，来源后置。
- data-model.md：聚焦实体、唯一标识、引用与派生约束、状态及迁移；无数据影响时说明不适用理由。
- contracts/：聚焦实际接口的输入输出、兼容性和错误语义；涉及流式响应时补充终止与中断语义；不虚构新接口。
- quickstart.md：给出最短验证路径、前置条件、实际命令、预期结果和常见排障。按需选用 npm run validate:data、npm test -- tests/[实际文件].test.js、npm run build、npm run test:e2e；生成时替换占位路径。端到端测试依赖构建产物与浏览器安装。npm run dev 仅启动前端，不能据此验证生产 AI Function；模拟界面与真实 Function 验证分开说明。
