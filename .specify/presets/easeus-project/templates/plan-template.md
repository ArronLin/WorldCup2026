沿用有效模板的分类、模式、设计基线、图片来源及偏差处理；非 UI 不生成本节，待确认先澄清。规划不自动授权运行或实施。

### UI Gate 1：编码前设计确认

在原计划或验收位置核对材料可读且足够、基线及主要验收明确、组件映射及验证方式可行、必要人工确认已获得。影响实现的缺口未解决时暂停相关 UI 实施，已确认且未变化内容不重复批准。

### UI Gate 2：初步 UI 验证方案

完整模式按依赖安排结构与主要控件、实际运行与当前截图、基线对照、重要偏差修正，再继续剩余业务逻辑及交互和适用视觉回归。首轮所需最小数据按需准备，模拟状态注明；轻量模式局部修改后完成对应验证。

填写浏览器及版本、系统、视口、缩放或 DPI、主题、字体环境、页面／状态、候选版本及未提交范围、验证者。证据沿用项目目录，未知先核实；环境不可比先校准。差异表仅含验收 ID、预期、实际、证据引用、类别、严重程度（阻断／重要／轻微）、修复建议。静态截图不能证明交互；像素相似度不能单独决定通过。未运行、无看图能力或仍有重要偏差时保持待验证／未通过，等待适用工具或人工，不用设计图、旧截图或构建成功替代。

两个 Gate 为 Agent 检查与必要人工确认约定，不是原生审批引擎。设计或实现变化只重开受影响项并重验失效证据，保留有效任务 ID 和决定；文档修订不自动授权编码。
