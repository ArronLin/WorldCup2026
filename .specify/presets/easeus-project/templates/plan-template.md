## 仓库验证入口与能力缺口

README 要求 Node.js 24 或更高版本，现有 CI 使用 Node.js 24。实际安装版本、生产运行版本及执行能力仍需按环境核实。按影响选择最短验证集合，写明目标、前置、预期结果与未覆盖范围：

| 用途 | 现有入口 | 适用限制 |
| --- | --- | --- |
| 前端运行 | npm run dev | 不启动生产 AI Function。 |
| 数据契约 | npm run validate:data | 核对本次标识、引用和值及双语词条是否在实际校验范围。 |
| 构建 | npm run build | 先校验数据，再生成 dist/。 |
| 单元及模块行为 | npm test | tests/**/*.test.js；默认 node，DOM 行为按需采用现有 jsdom。 |
| 覆盖率采集 | npm run test:coverage | 核对包装脚本及 V8 配置能否覆盖本次真实生产逻辑。 |
| 浏览器行为 | npm run test:e2e | 先构建当前候选；确认 4173 preview 与 dist/ 对应版本，防止复用旧服务。 |
| AI 演示 | /?mock | 仅验证演示行为。 |
| Function 本地调试 | npx netlify-cli dev | 按 README 配置必要环境，实际可用性待运行验证。 |

现有配置不能直接记为能力已具备或验证通过。必要的本地采集、运行或排障建设进入相关原生任务；沿用已有工具和 CI，不新增 CI 接入或 HTML 报告任务。覆盖率等交付门槛与真正实施前置分开，独立业务工作不因无关工程适配而全部阻塞。

### 变更范围行覆盖率字段

来源为输入 effective_policy：变更范围单元行覆盖率门槛 80%。填写已核实比较基线、纳入的自有可执行业务逻辑、可执行行分母、命中行、排除项及理由；不以全项目指标替代，不按文件类型整包排除。无可靠采集能力记“未核验／能力缺口”，不能由空分母或脚本退出成功推断达标。

当前 scripts/check-added-coverage.mjs 采用 Istanbul 源映射后的可执行语句起始行；变化的多行代码映射到所属语句起始行，排除注释和空白。核对该口径适用于本次变更及采集结果；必要时安排能力建设，不直接宣称可靠。

基线文件与 Git 比较提交二选一。提交模式可使用 `npm run coverage:added -- --base-commit <已核实的40位提交> --output coverage/coverage-added.json`，先确认比较提交可解析且符合本次范围。清单模式核对实际清单及来源，不固定旧功能基线。显式输出到既有 coverage/，避开脚本默认的旧功能目录。这里说明现有脚本用途，不增加报告或证据包政策。

## 涉及界面时的组件映射与验证字段

仅对当前需求判定为 UI 的部分填写，引用规格中的设计基线、验收 ID、版本和确认范围。非 UI 不生成界面映射和截图安排；待确认先澄清，不因本项目是网页而默认所有任务涉及 UI。

组件映射填写：需求／验收 ID、页面与控件、源码位置、复用／新增及理由、状态与事件、样式来源、目标浏览器及实际运行／视觉／交互验证方式。复用定位包括 components.css 的国旗、球队标识、阶段徽章与比赛卡片，以及 src/utils.js 的本地化与格式化工具。

主题来源为 tokens.css：深浅背景、强调与语义颜色、Inter 和中文字体回退、间距、圆角、最大内容宽度及顶栏变量；基础布局查 base.css，页面和聊天样式查 pages.css、chat.css。涉及玻璃背景时核查 --glass-bg 与 --bg-glass 的实际级联，不将命名疑点作为设计规范或附带修复范围。

依据 answers.Q-review-ui-lifecycle，仅对受影响交互核对 src/router.js 的 resolveFocusTarget、焦点可用性与回退、选区、滚动和生命周期订阅，以及相关控制器的绑定、解绑和过期响应处理。不能把现有源码结构写成行为验证已经通过。

沿用公司第一道界面门禁，编码前确认材料实际可读且充分、基线及主要验收明确、组件映射和验证方式可行、必要人工确认已获得；实现相关缺口未解决时暂停，已确认且未变化的内容不重复批准。

依据 answers.Q-review-ui-preview，初步界面验证只用于受影响 UI。完整模式规划“结构与主要控件 → 当前候选运行与截图 → 基线对照 → 重要偏差修正 → 剩余业务逻辑 → 交互及适用视觉回归”，准备最小必要数据并标明模拟状态。适用 TDD 继续有效。

第二道界面门禁使用实际截图或事先约定的其他可核验证据；记录页面／状态、候选修订与未提交范围、浏览器、窗口尺寸、DPI、主题、语言、字体环境及验证者。环境不可比先校准，静态截图不证明交互；不能运行或看图时保持待验证，等待适用工具或人工验证。差异表仅记录验收 ID、预期、实际、证据引用、类别、严重程度（阻断／重要／轻微）和建议。轻量模式在已有工件中完成局部验证。

## 派生产物的项目字段

- research.md：只保留决定、备选、取舍和关键依据，摘要集中说明未决影响。
- data-model.md：受影响实体、标识与引用约束、状态及迁移；不因静态 JSON 自动增加数据库设计。
- contracts/：受影响接口、字段、兼容性、错误及流式终止／中断语义，覆盖实际消费方。
- quickstart.md：当前候选的最短验证路径、必要数据和环境、实际命令或操作、预期结果及排障；区分前端、演示和真实 AI 集成。

派生文档同样采用简体中文、摘要先行、主题分层和依据后置，不保存原始日志或空工件。研究前和设计后沿用原生宪法检查；本地验证与必要人工交接分开，交接引用既有约定。
