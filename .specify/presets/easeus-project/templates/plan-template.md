## EaseUS：plan 阶段规则与依据
使用当前规则快照和已评审项目约定；为适用规则记录落实方式及完成条件。

### 交互与产物语言
所有面向人的自然语言内容，包括标题、小标题、表头、任务类别、状态说明、目标、依赖与验证文字，使用简体中文；命令、文件路径、API 与代码标识符、协议关键字和框架固定标记保持原样。引用必须保留的英文固定标记时，应在相邻位置提供简体中文说明；不得照抄基础模板的英文标题作为最终文档标题。

### 真实 TDD
新增或修改可单测行为及修复缺陷时，先编写测试并实际运行，确认测试因预期行为尚未实现而失败，再编写最小实现使测试通过，随后按需重构并回归验证。依赖、环境或语法错误不能作为有效的 Red；不得将事后补写测试宣称为 TDD。

### 可计量新增业务逻辑测试覆盖率
对仓库现有工具能够可靠采集的新增或修改自有生产代码可执行业务逻辑，单元测试覆盖率不低于 80%；优先采用语句或分支覆盖率，现有工具仅提供行覆盖率时可使用行覆盖率。纯声明式界面（包括 QML）、生成代码、资源和配置不纳入百分比分母，但相关属性、绑定、信号、状态变化及关键用户场景必须通过自动化行为测试；复杂业务逻辑应优先移入可单测模块。无可靠采集能力时明确记为不适用或能力缺口，不得填成 0% 或 100%，也不得用 qmlprofiler 等性能分析事件作为覆盖率证明。

### 有效测试与验证
测试必须调用真实被测生产逻辑，包含能识别错误行为的断言并实际发现和执行。禁止占位成功、恒真断言、mock 掉被测核心与静默跳过；未实际执行测试不得宣称通过。关键控制逻辑采用可恢复的反向验证或适用变异测试。

### 来源与事实核实
知识库与源码说明现状，已确认需求定义期望；关键结论记录来源与适用版本，未知必须明确，现状缺陷不得自动固化为规范。
正文开头增加“评审摘要”，依次展示方案摘要、变更地图、关键决策、需确认项和风险。决策说明选项、选择理由和影响；正文按组件与依赖展开，来源和技术细节后置。
派生文档同样采用评审优先结构：research.md 只记录决策、备选方案与依据；data-model.md 聚焦实体、约束、状态与迁移；contracts/ 聚焦接口、兼容与错误语义；quickstart.md 只给最短验证路径、预期结果和排障。不得复制背景或保存原始日志。

## 项目约束与验证安排

按实际变更核对静态快照说明、数据契约校验以及 AI 不可用时核心浏览。赛事数据或消费契约变更时，安排覆盖受影响标识、引用关系和双语词条的校验；先核对 `npm run validate:data` 的现有覆盖范围，存在缺口时安排建设任务，不因命令已配置就宣称能力完备。

结合实际变更选择 `npm test`、`npm run build` 和必要的 `npm run test:e2e` 等已有入口；`npm run build` 包含数据校验，端到端验证依赖构建产物及浏览器。普通 `npm run dev` 不启动生产 AI Function；涉及该边界时明确环境及替代验证方式。浏览器支持矩阵和部署运行版本未确认时标为待确认，不推断支持承诺。

对可单测行为按当前有效规则先测试并实际运行，确认因预期行为未实现而失败后再实现；测试调用真实生产逻辑并具有有效断言，关键控制逻辑安排可恢复反向验证或适用变异测试。覆盖率对现有工具可靠采集的新增或修改自有生产可执行业务逻辑采用不低于 80% 的单元测试门槛，优先语句或分支，工具仅能提供行覆盖时采用行覆盖；声明式界面、生成代码、资源和配置不计入分母，但相关属性、绑定、信号、状态变化及关键用户场景需自动化行为测试。无法可靠采集时区分不适用与能力缺口并安排必要建设，不填 0% 或 100%。沿用现有工具及 CI，不增加 CI 接入、强制报告或基线快照任务；不得将某个现有功能的覆盖率清单固化为通用基线。

## 派生文档重点

- `research.md`：仅保留决策、备选及依据。
- `data-model.md`：聚焦实体、约束、状态和迁移。
- `contracts/`：聚焦接口、兼容性和错误语义。
- `quickstart.md`：给出最短验证路径、预期结果及排障。

各文档摘要先行，来源和技术细节后置；沿用规格已有的 UI 图片来源，不复制资源。实际命令和结果在对话中简述，未执行不得写成通过。
