## 项目评审维度

按实际范围选择完整性、清晰性、一致性、可验证性、范围边界、异常、兼容性、数据契约、双语语义、AI 降级及 UI 维度。每项只提出一个可回答的问题，标明顺序 `CHKxxx`、优先级、单一风险理由、实际需求／验收 ID 及文档位置；需求缺失时定位准确章节和缺口，不复制规格正文。

项目问题方向按需分别生成：

- 静态属性：某项赛事信息需求是否明确静态快照属性？
- 数据约束：某一标识或引用约束是否明确？
- 双语语义：某一受影响词条的中英文业务含义是否一致？
- 深链接：某一缺省或无效参数的用户结果是否明确？
- 持久化异常：某一读写失败的可观察行为是否明确？
- AI 降级：AI 不可用时某项核心浏览能力是否明确保留？
- 兼容迁移：某一受影响消费契约的迁移影响是否说明？

生成时将每个方向落实到本次实际 ID 和位置，无关方向不输出；涉及多个标识、状态或边界时按独立问题拆分。

格式示意：

- [ ] CHK001 [优先级：高] [维度：可验证性] [FR-xxx；spec.md 对应章节／验收 ID] 该需求是否定义可观察的成功结果？（理由：[单一风险]）

## UI 需求质量的项目定位（条件适用）

沿用规格的 UI／非 UI／待确认分类、模式及依据。非 UI 不生成 UI 问题；待确认定位缺口，不自行按非 UI 跳过。设计材料读取状态、可复核版本、确认范围、某一状态验收、组件映射、视觉验证可行性和交互验收分别形成单问题条目。

项目映射按实际影响核对 `index.html`、`src/views/`、`src/features/`、`src/styles/components.css`、`src/styles/tokens.css`；主题及语言刷新定位 `src/app.js`，焦点方案定位 `src/router.js` 的 `focusKeys`。检查需求、基线、组件映射、任务和验收能否追溯，不因现有主题、语言或窄屏实现自动增加支持承诺。

需求图片沿用规格原引用，不重复复制资源；分别检查某一来源缺口或图文冲突是否明确。两个 UI 检查关口只评审条件与验证方案是否完整，不能用“截图已取得”或“交互测试已通过”冒充需求质量问题。只读一致性分析仅报告具体位置、影响和建议。
