## EaseUS：tasks 阶段规则与依据
使用当前规则快照和已评审项目约定；为适用规则记录落实方式及完成条件。

### 交互与产物语言
所有面向人的自然语言内容，包括标题、小标题、表头、任务类别、状态说明、目标、依赖与验证文字，使用简体中文；命令、文件路径、API 与代码标识符、协议关键字和框架固定标记保持原样。引用必须保留的英文固定标记时，应在相邻位置提供简体中文说明；不得照抄基础模板的英文标题作为最终文档标题。

### 真实 TDD
新增或修改可单测行为及修复缺陷时，先编写测试并实际运行，确认测试因预期行为尚未实现而失败，再编写最小实现使测试通过，随后按需重构并回归验证。依赖、环境或语法错误不能作为有效的 Red；不得将事后补写测试宣称为 TDD。

### 可计量新增业务逻辑测试覆盖率
对仓库现有工具能够可靠采集的新增或修改自有生产代码可执行业务逻辑，单元测试覆盖率不低于 80%；优先采用语句或分支覆盖率，现有工具仅提供行覆盖率时可使用行覆盖率。纯声明式界面（包括 QML）、生成代码、资源和配置不纳入百分比分母，但相关属性、绑定、信号、状态变化及关键用户场景必须通过自动化行为测试；复杂业务逻辑应优先移入可单测模块。无可靠采集能力时明确记为不适用或能力缺口，不得填成 0% 或 100%，也不得用 qmlprofiler 等性能分析事件作为覆盖率证明。

### 有效测试与验证
测试必须调用真实被测生产逻辑，包含能识别错误行为的断言并实际发现和执行。禁止占位成功、恒真断言、mock 掉被测核心与静默跳过；未实际执行测试不得宣称通过。关键控制逻辑采用可恢复的反向验证或适用变异测试。

### 来源与事实核实
知识库与源码说明现状，已确认需求定义期望；关键结论记录来源与适用版本，未知必须明确，现状缺陷不得自动固化为规范。
正文开头增加“评审摘要”，显示任务规模、依赖、阻塞项、需确认内容和各类任务数量；不另建与正文重复的测试汇总表。
保持按用户故事组织；每个故事内部依次设置“测试任务（先行）”“实施任务”“验证任务”，不得把测试集中到远离需求的统一阶段。每条任务在官方 ID、`[P]`、`[USn]` 之后标记一个类型：`[测试]`、`[实现]`、`[验证]`、`[准备]` 或 `[文档]`。测试任务写明层级、目标行为、测试入口和关键断言，验证任务写明实际命令或可观察结果；不另建重复汇总表。
所有面向人的标题、小标题、表头、任务类别和状态说明使用当前语言规则；命令、路径、代码标识符和框架固定标记保持兼容。
记录来源、适用版本、关键差距与待决定事项。保持该阶段原有职责，不将未执行验证标为通过。

## 任务类型与执行约定

任务格式为 `- [ ] T001 [P] [US1] [测试] 描述及实际路径`；可选的 [P] 与故事标记保持官方顺序，类型标签紧随其后。每条任务只使用一个主要类型：[测试]、[实现]、[验证]、[准备] 或 [文档]。共享准备任务没有所属故事时省略 [USn]，不虚构故事。

保留必要共享准备与基础工作，各用户故事内部依次使用“测试任务（先行）”“实施任务”“验证任务”。可单测行为与缺陷修复的测试任务不是可选项。没有适用可单测行为时，在对应故事测试小节简述理由，并按需要安排界面行为测试；不生成占位成功测试。

#### 测试任务（先行）

#### 实施任务

- [ ] T002 [USn] [实现] 在[实际生产文件路径]实现[行为]，使 T001 的测试通过，并按需重构；依赖 T001 的有效预期失败。

#### 验证任务

- [ ] T003 [USn] [验证] 执行 npm test -- tests/[实际文件].test.js，预期[目标用例实际发现并执行且关键断言通过]；对[关键控制逻辑]执行[具体可恢复反向验证或适用变异命令]，确认测试能识别错误行为并恢复后回归。
- [ ] T004 [USn] [验证] 执行[本故事适用的实际数据校验、构建、覆盖率或端到端命令]，预期[明确结果或可观察行为]。

## 项目验证与依赖补充

测试调用真实生产逻辑，不 mock 掉被测核心，不以恒真断言、静默跳过或环境错误代替有效验证。实际失败确认与通过结果在对话中简述，不创建强制 Red/Green 收据。

将适用的单元、DOM、契约、端到端和覆盖率验证放在所属故事内；不把测试集中到末尾阶段。跨故事共享检查只安排一次，并注明必要依赖，不复制成各故事的重复汇总。

复用仓库 tests/、e2e/、src/、public/ 和 netlify/functions/ 中本次实际受影响路径。验证命令从当前 package.json 与计划选取；Playwright 使用构建产物，需先满足构建及浏览器前置条件。覆盖率仅使用 effective_policy 的门槛与范围，核对已有工具的比较基准与可靠性；缺少能力时安排明确的[准备]或[实现]任务，并在相关故事验证前完成。

[P] 只用于不存在文件冲突及前置依赖的任务；同一行为的有效失败确认必须先于实现。文档任务只更新必要的原生框架文档；不增加基线快照、evidence 目录、追踪映射、逐任务验收说明、截图、HTML 报告或 CI 接入任务。
