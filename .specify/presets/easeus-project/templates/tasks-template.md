## 项目任务摘要字段

合并至开头摘要：本轮故事与范围、主要变化、真正前置依赖、集中待确认及阻塞、主要风险和适用任务类别数量。不建立重复任务表或测试汇总表，不预填完成结果。

## 故事内的类型与成果字段

保持用户故事组织，仅输出适用的“测试任务（先行）”“实施任务”“验证任务”；准备与文档任务归入原生适当位置。每条任务在官方 ID、可选 [P]、适用 [USn] 后添加一个类型：[测试]、[实现]、[验证]、[准备] 或 [文档]。不为凑章节制造任务，不把测试集中到统一末尾阶段。

当前 effective_policy 启用 TDD，仅对适用行为要求测试先于对应实现；以后规则停用时不恢复。按可检查成果形成测试与对应实施的小闭环，不要求所有故事的测试先写完。测试写明层级、真实生产逻辑、目标行为、入口及关键断言；实现写明范围、成果及对应测试；独立验证目标存在时才单列验证任务，写实际命令或可观察结果。保留当前有效规则规定的重构、特征测试、纯视觉和环境限制处理，不将依赖或语法错误当作有效失败测试。

格式示意，生成时替换占位并使用实际稳定编号：

```markdown
### 测试任务（先行）

- [ ] T001 [P] [US1] [测试] 在 tests/<相关模块>.test.js 对 src/<真实模块>.js 编写单元测试；目标：<行为与边界>；入口：npm test -- tests/<相关模块>.test.js；关键断言：<能识别错误行为的结果>。

### 实施任务

- [ ] T002 [US1] [实现] 在 <实际路径> 实现 <单一可检查成果>，通过 T001 对应行为测试。
  依赖：T001

### 验证任务

- [ ] T003 [US1] [验证] 执行 <实际命令或操作>，核对 <独立验证目标的可观察结果>。
  依赖：T002
```

示例不是固定任务清单；层级按实际填写单元、模块集成或端到端。[P] 表示真正前置满足后可安全并行，共享文件冲突保留顺序。覆盖率适配和整轮浏览器验证不默认阻塞无关逻辑任务。字段、算法和场景引用规格、模型或契约，不重复粘贴；失败、通过及重构不各建复选框，也不新增通用收据。

## 项目验证入口选择

按故事实际影响从以下入口选择，完整参数与前置可引用 quickstart.md 的准确位置：

- tests/ 下的 Vitest 与 npm test；DOM 行为按需使用已有 jsdom，测试调用真实生产逻辑。
- 数据和双语契约采用 npm run validate:data，补足本次受影响约束的有效断言。
- 构建采用 npm run build；端到端采用 e2e/ 与 npm run test:e2e，先生成当前 dist/ 并确认 4173 服务版本。
- 变更覆盖率采用计划核实的 npm run test:coverage 与 coverage:added 参数，显式输出到既有 coverage/；按当前 effective_policy 检查变更范围单元行覆盖率 80%，不固定旧功能清单，不增加 HTML 报告任务。
- AI 按规格选择演示、浏览器直连或 Netlify Function 的受影响路径，覆盖适用的外传、凭据、事实依据和降级行为；演示通过不替代真实集成。

能力不足时把必要本地建设或排障纳入相关原生任务并说明阻塞，不新增 CI 接入。其他环境能自动执行的测试仍归自动化，不因当前机器限制转成人工。

## 界面故事的条件式依赖

只对当前需求确定涉及 UI 的部分启用，引用 spec.md 的基线及 plan.md 的实际组件映射；待确认先澄清，非 UI 不生成界面分组或截图任务。本轮适配不运行应用，也不宣称设计获批。

完整模式以真正依赖安排：编码前设计确认 → 原生 DOM 结构与主要控件及最小必要数据 → 当前候选实际运行与截图 → 对照确认基线 → 修正重要偏差 → 剩余业务逻辑 → 交互及适用视觉回归。适用测试先行约束继续有效；即使章节按类型分组，剩余业务实施也明确依赖初步界面验证和必要修正，不能仅凭章节顺序跳过。

实施范围引用 src/views/、src/features/、components.css、tokens.css 等实际映射；重渲染行为引用当前 src/router.js 的焦点、选区、滚动及生命周期设计，不固化某个现有功能。模拟状态必须标明，不能代替最终集成验证。

界面验证写明页面／状态、候选修订及未提交范围、浏览器、窗口尺寸、DPI、主题、语言和验证者，取得当前运行截图或事先约定的可核验结果；在已有验收或任务位置记录简短差异。交互通过实际操作或行为测试验证。重要偏差未处理时保持阻塞，不能运行或看图时保持待验证。轻量模式在局部修改后完成相应验证，不生成整套附加文档。
