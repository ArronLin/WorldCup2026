## EaseUS：tasks 阶段规则与依据
使用当前规则快照和已评审项目约定；为适用规则记录落实方式及完成条件。

### 交互与产物语言
使用简体中文交互和编写自然语言产物；命令、标识符与固定标记保持兼容。

### 真实 TDD
新增或修改可单测行为及修复缺陷时，先编写测试并实际运行，确认测试因预期行为尚未实现而失败，再编写最小实现使测试通过，随后按需重构并回归验证。依赖、环境或语法错误不能作为有效的 Red；不得将事后补写测试宣称为 TDD。

### 新增生产代码单测行覆盖率
仅新增自有生产代码的单元测试行覆盖率不低于 80%；以本功能明确基线计算新增可执行行的未舍入汇总比值，不要求存量代码或全项目达到 80%。集成或端到端覆盖率不能替代该指标，无新增可执行行记为不适用。

### 有效测试与验证
测试必须调用真实被测生产逻辑，包含能识别错误行为的断言并实际发现和执行。禁止占位成功、恒真断言、mock 掉被测核心与静默跳过；未实际执行测试不得宣称通过。关键控制逻辑采用可恢复的反向验证或适用变异测试。

### 来源与事实核实
知识库与源码说明现状，已确认需求定义期望；关键结论记录来源与适用版本，未知必须明确，现状缺陷不得自动固化为规范。
记录来源、适用版本、关键差距与待决定事项。保持该阶段原有职责，不将未执行验证标为通过。






## 项目任务生成与执行补充

沿用现有任务 ID、用户故事分组及依赖格式，以下要求用于生成实际任务，不保留为固定功能任务清单。

### 测试先行依赖

对新增或修改可单测行为及缺陷修复，生成以下依赖顺序；基础模板的“测试可选”示例不改变当前有效规则：

1. 在 tests/ 的实际发现路径编写调用真实生产逻辑的测试，运行 `npm test -- [实际测试文件]`，确认因预期行为未实现而失败。依赖、环境或语法错误先修复，不能作为有效失败。
2. 对应生产实现任务依赖上述测试任务完成；两者不得标为相互独立的并行任务。
3. 实现后运行相关测试，再按需重构并执行受影响回归；关键控制逻辑安排可恢复的反向验证或适用变异验证，并恢复后回归。

测试环境或覆盖率能力不足时，先生成 plan.md 已识别的必要建设任务；仅创建配置不能完成能力建设。

### 实际路径与验证任务

- 使用 plan.md 中核实的生产、词典、数据与测试路径；现有 Vitest 发现 tests/**/*.test.js，DOM 行为选择适用环境。
- 数据或词典变更安排 `npm run validate:data`；构建验证使用 `npm run build`。避免重复执行没有新增验证价值的步骤。
- 涉及浏览器交互时，按计划更新 e2e/ 测试并在构建后运行 `npm run test:e2e`；当前预览服务使用 4173 端口，浏览器安装是运行前提。
- 涉及 AI 时，区分前端 mock、真实 Function 与上游服务验证，检查 AI 不可用时核心浏览仍可用。
- 覆盖率验证沿用 `npm run test:coverage` 和现有新增行检查工具，使用本功能已明确的基线及显式参数。执行 `npm run coverage:added -- --baseline [已核实基线路径] --report coverage/coverage-final.json --output coverage/coverage-added.json` 前核对输入可用性；需要重建既有基线时按计划使用 `coverage:baseline` 的实际参数。
- 新增自有生产代码单测行覆盖率以未舍入汇总比值达到 80% 为准；无新增可执行行记为不适用，不以全项目或端到端指标替代。

任务产物保持为原生文档、代码、测试和必要任务状态。实际命令、结果及受阻原因在对话中简述；不增加强制 Red/Green 收据、基线快照、独立 evidence、追踪映射、逐任务验收说明、截图、HTML 报告或 CI 接入任务。未实际发现并执行的测试不得标为通过。
