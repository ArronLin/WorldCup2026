## EaseUS：tasks 阶段规则与依据
使用当前规则快照和已评审项目约定；为适用规则记录落实方式及完成条件。

### 交互与产物语言
使用简体中文交互和编写自然语言产物；命令、标识符与固定标记保持兼容。

### 真实 TDD
新增或修改的可单测行为与缺陷修复执行真实 Red → Green → Refactor，记录实际失败与通过证据，不伪造历史 Red。

### 新增生产代码单测行覆盖率
仅新增自有生产代码的单元测试行覆盖率不低于 80%；以本功能明确基线计算新增可执行行的未舍入汇总比值，不要求存量代码或全项目达到 80%。集成或端到端覆盖率不能替代该指标，无新增可执行行记为不适用。

### 有效测试与完成证据
测试必须调用真实被测生产逻辑，包含能识别错误行为的断言并实际发现和执行。禁止占位成功、恒真断言、mock 掉被测核心、静默跳过与无证据勾选完成；关键控制逻辑采用可恢复的反向验证或适用变异测试。

### 来源与事实核实
知识库与源码说明现状，已确认需求定义期望；关键结论记录来源与适用版本，未知必须明确，现状缺陷不得自动固化为规范。
记录来源、适用版本、关键差距与待决定事项。保持该阶段原有职责，不将未执行验证标为通过。




## 项目增补：任务依赖与完成证据

按当前 effective_rules 和 plan.md 生成实际任务。当前已启用 tdd、tests、coverage，基础示例中的“测试可选”不得取消适用任务；以后未启用的规则不得从本模板历史文本恢复。以下提供生成字段和依赖约束，不作为已完成任务或固定功能清单。

### 每项任务的补充字段

保持基础格式 `- [ ] Txxx [P?] [USx] 描述及实际文件路径`；在任务下补充：

- 依据：[FR／验收场景／契约／适用宪法原则或有效规则]。
- 前置任务：[具体 ID；无则写无]。
- 完成判据：[可检查产物与结果]。
- 完成证据：[实际命令或操作、时间、执行环境、基线及工作区状态、日志／报告路径与结果；未执行时明确写未执行]。
- 事实状态：[verified／inferred／unknown；不适用另附理由和依据]。

### 按用户故事落实工程规则的依赖

1. 基线与影响确认：核对当前源码、已有未提交修改归属、受影响调用方及需求映射；建立本功能可复核基线。
2. 能力建设：仅对计划已识别的缺口生成任务。测试发现和执行能力必须在依赖它的 Red 任务前可用；新增行覆盖率采集、行映射和门槛能力必须在最终覆盖率判定前完成并验证。不得把所有故事都阻塞在无关建设任务上。
3. Red：为适用行为编写调用真实生产逻辑的测试并实际运行，记录目标行为失败；收集错误、缺依赖或服务不可达不能替代行为 Red。
4. Green：依赖对应 Red 证据，实现目标行为并实际运行相关测试，记录通过证据。
5. Refactor：依赖 Green；执行必要重构并复跑相关测试。无需代码重构时记录审视结论与通过记录，不虚构改动。
6. 测试有效性验证：关键控制逻辑采用计划中适用的可恢复反向验证或变异测试，记录错误行为被识别、恢复状态及恢复后通过结果。不得将其冒充先于实现发生的历史 Red。
7. 按影响执行数据契约、双语状态、集成、浏览器或 Function 环境验证；端到端任务依赖构建产物和浏览器环境，Function 验证依赖相应服务环境。
8. 在最终变更状态生成新增生产代码单测行覆盖率证据，并完成故事验收及相关回归；任何后续生产代码变更须使受影响证据重新对应最终状态。

各行为的 Red → Green → Refactor 顺序不得用 [P] 绕过。只有文件和其他共享资源无冲突、前置证据已满足的任务才标 [P]；数据、词典、共享模块或报告路径冲突也需串行安排。

### 项目验证任务的生成维度

| 本功能影响 | 应生成的任务内容 | 完成证据 |
| --- | --- | --- |
| 数据或词典 | 更新适用契约与校验；运行 npm run validate:data 及关联测试 | [发现的约束、实际结果及报告] |
| 共享领域行为 | 生产逻辑单测、跨调用方语义一致性及适用反向验证 | [真实入口、断言、失败与通过记录] |
| 用户交互或语言切换 | 对应验收场景与明确状态清单的浏览器验证 | [语言切换实际发生、状态判定及执行结果] |
| 构建或静态资产 | npm run build，检查相关产物 | [数据校验、构建结果及产物检查] |
| 端到端路径 | 构建后使用现有 Playwright／Chromium 基线 | [实际发现和执行数、场景结果、环境] |
| AI／Function | 按已评审策略验证请求、HTTP／SSE、预算、限流及受影响资源生命周期 | [相应环境和故障场景证据；mock 范围单列] |
| 验证能力不足 | 建设所缺测量或测试能力，再实际验证其能识别失败 | [建设产物、有效性验证和恢复结果] |

仅生成与本功能相关的行，不将当前历史页面、具体球队或届次固定为每项功能的任务。

### 新增行覆盖率完成记录

- 基线与最终状态：[明确标识及未提交文件快照／哈希]。
- 新增自有生产代码与可执行行集合：[路径、行映射、纳入和排除依据]。
- 单测采集：[命令、实际发现及执行数、未加载生产文件的处理、原始报告路径]。
- 分子 C／分母 D：[被单测覆盖的新增可执行行数／新增可执行行总数]。
- 判定：[D > 0 时，未舍入汇总 C / D ≥ 0.8；D = 0 时附证据记不适用]。
- 不得以全项目百分比、文件百分比平均值、集成或端到端覆盖率替代本项。

### 完成与评审边界

仅在完成判据和实际证据满足后勾选任务。失败、未执行、阻塞和不适用分别说明；不能以存在配置、存在测试文件、历史注释或检查表已勾选替代执行证据。自定义 checklist 的标记归评审者维护，本任务清单不得代改其标记以解除评审门槛。
