## UI 故事的依赖增补

沿用规格分类、模式、设计基线及计划组件映射，非 UI 不生成 UI 分组或截图任务，待确认先澄清。完整模式在故事内部建立依赖：编码前设计确认 → 结构与主要控件 → 实际运行与当前截图 → 基线对照 → 阻断和重要偏差修正 → 剩余业务逻辑 → 交互及适用视觉回归。测试仍先于对应实施；中途验证项可列在故事的验证分组，但后续实施显式依赖其 ID，不能因排版顺序跳过。

必要最小数据用 `[准备]` 项，注明模拟状态，不能替代集成验证。复用 `src/views/`、`src/features/`、`src/styles/` 的已确认映射；沿用规格图片不重复复制。实际截图及差异按有效模板 UI Gate 2 记录在既有任务／验收位置，包含页面／状态、候选版本及未提交范围、环境和验证者，沿用项目目录。交互另做操作或行为测试。未运行、证据不足或有重要偏差时保持待验证／未通过并阻塞依赖项，独立任务继续；轻量模式完成局部对应验证，不生成整套附加文档。

设计或相关实现变化保留有效任务 ID，只重开受影响项并重新核验失效证据；当前阶段生成任务不自动授权实施。

## 条件式人工交接增补

先读已有验收、审批、发布约定和当前验收场景。只按已有约定或明确需求生成必要人工项，默认不新增最终人工验收，已有覆盖不重复；负责人或发布影响不明时澄清。本机设备、数据或权限不足的自动化任务仍属自动化测试，写明阻塞原因；失败和缺失实现不得转成人工任务。

需要混合任务或显式依赖时，在原 `tasks.md` 写入 `<!-- repo-sdd:hybrid-tasks:v1 -->`。保留原生标记，类型标签之后按需加 `[人工]`，无执行者标签沿用 Agent。缩进说明使用 `依赖：T010, T011`；“类型”填写开发、自动化测试、人工测试、评审、验收或其他。人工项填写负责人、环境、原因、步骤、预期、证据和“发布必需：是／否”，默认阻塞发布；确需正式签收才写“最终验收：是”。无人工项不生成空分组，不新增平行清单或证据包。明确停用使用 `<!-- repo-sdd:hybrid-tasks:v1 {"enabled":false} -->`，旧清单先读原约定，不自动转换。

执行前读取整份清单，核实当前 Spec Kit 项目指南的运行组件路径，运行 `workflow/run.ps1 inspect-tasks --tasks <仓库相对路径>`，或同目录 `python -B runtime.py inspect-tasks --project . --rules <当前规则快照> --tasks <仓库相对路径>`。可按 `--story`、`--phase`、可重复的 `--task-id` 限批次，前置仍跨批次检查。只推进 `ready_ai`，完成后更新 AI 复选框并重算；人工项不勾选，其依赖项保持阻塞，继续独立任务。非法依赖及循环须报告并修正，不能靠自由文本跳过任务。

交接在既有位置列已完成／剩余 AI 数、待人工项、阻塞及原因、实际自动化结果和可交接范围，区分当前批次暂无可执行项与整份 AI 清单完成。人工实际通过后，仅授权人员填写执行人、执行日期（YYYY-MM-DD）、实际环境、结果：通过、结果证据并勾选。失败保持未勾选，填写结果：失败、问题编号、复现步骤和证据，修复项用关联任务引用原 ID。延期按原流程批准，填写发布必需：否、延期批准人、延期截止日期、延期原因并保持待验收；Agent 不代填人工结果，不删除未通过项。

最终实际核对实现差距和测试后，才在适当已完成项记录“实施复核：通过”“复核修订：<inspect-tasks 返回的 revision>”；正式人工验收由授权人员填写，无人工要求可复用已有 AI 验证项。当前修订记录齐备后才报告“已收尾”，测试、CI 和审批真实性由原机制核验。需求变化保留历史并重开受影响项，只读不改状态，续做先读剩余任务。

Spec Kit 的 implement 推进可执行 AI 项，最终交付仍满足原生全量完成条件；analyze 不把明确交接当作遗漏，checklist 只评需求质量；converge 在人工未完成时报告“待人工验收”，有阻塞实现时不得报告全量收敛。官方 Bug 沿用 `assessment.md`、`fix.md`、`test.md`，未执行不得填固定结果 `Result: Passed`，不自动推进阶段。
