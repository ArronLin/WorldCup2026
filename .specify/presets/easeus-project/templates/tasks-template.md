## 故事内任务的项目格式

每个故事按适用任务设置“测试任务（先行）”“实施任务”“验证任务”，没有适用任务的分组不输出。保留官方 ID、可选 `[P]`、适用 `[USn]`，随后加入一个 `[测试]`、`[实现]`、`[验证]`、`[准备]` 或 `[文档]` 类型标签。共享准备和文档任务同样标类型，不另建重复汇总表。

### 测试任务（先行）

格式示意，生成时替换实际编号和内容：

- [ ] T001 [P] [US1] [测试] 在 `tests/<实际名称>.test.js` 添加[单元／DOM／契约]测试，调用 `<真实生产入口>`，验证[需求 ID 的目标行为]，断言[关键结果]；执行 `npm test -- tests/<实际名称>.test.js`。

当前 effective_policy 启用 TDD，适用行为的测试先于对应实现并实际运行；基础示例的“测试可选”不覆盖本次规则。纯重构、配置、纯视觉及无法可靠测试先行的情形沿用 effective_rules 的适用处理，不伪造失败。测试入口选用 `tests/`，DOM 测试按需显式启用 jsdom，浏览器集成放在 `e2e/`；环境自测不能代替生产行为验证。仅按高风险或断言疑点安排反向验证，不将历史功能专用变异脚本套用于全部功能。

### 实施任务

- [ ] T002 [US1] [实现] 在 `<计划确认的实际路径>` 完成[独立且可检查的需求行为及完成条件]。
  依赖：T001

从计划选择 `src/views/`、`src/features/`、`src/shared/tournament-query/`、`public/data/`、`public/i18n/`、`netlify/functions/` 的实际路径；仅安排本次涉及的工作，不将全部项目能力变成每个故事的必做项。`[P]` 只用于无前置依赖且不争用文件的任务。

### 验证任务

- [ ] T003 [US1] [验证] 执行 `<已核实的实际命令>`，核对[需求／验收 ID]的[可观察结果]。
  依赖：T002

按实际影响选择 `npm test -- <实际测试文件>`、`npm run validate:data`、`npm run build`、`npm run test:e2e -- <实际测试文件>`。浏览器验证前构建并核对 4173 服务为当前产物；涉及 Function 时安排服务端环境验证，区分 mock、BYOK 与 Function 结果。

覆盖率任务使用计划明确的 80% 变更范围单元行口径、适用基线及输出位置，避免历史功能默认路径。可靠采集缺口落实必要建设任务并保持未核验，不把配置存在当作完成。测试靠近所属故事，不集中到末尾阶段；实际命令与结果在对话简述，不新增通用 Red/Green 收据、逐任务验收说明、HTML 报告、证据包或 CI 接入任务。

## UI 故事的项目依赖（条件适用）

引用本次规格的分类、模式、设计基线和计划组件映射。非 UI 不增加 UI 分组、截图任务或检查点；待确认先澄清。

完整模式在同一故事内建立依赖：编码前设计确认 → 结构与主要控件 → 实际运行与当前截图 → 对照基线 → 修正阻断及重要偏差 → 剩余业务逻辑 → 交互及适用视觉回归。测试先于对应实现；中途验证可列在该故事的验证分组，但后续实施必须显式依赖对应验证 ID，排版顺序不能覆盖依赖。

首轮必要最小数据使用 `[准备]`，注明模拟状态；不替代最终集成验证。实施范围引用计划中的 `index.html`、视图／特性、组件和样式实际映射。涉及路由重渲染时，验证新焦点标识与 `src/router.js` 白名单协同、状态保持和旧异步结果处理；涉及文案时验证受影响中英文词条及刷新链路。

实际截图及短差异表记录在既有任务／验收位置，字段和判定完整沿用公司及本次输入的初步 UI 验证约定；证据目录按项目当前约定核实。交互需操作或行为测试。未运行、证据不足或仍有重要偏差时保持待验证／未通过并阻塞依赖项；轻量模式仅完成局部对应验证。设计或实现变化保留有效 ID，只重开受影响项并重核失效证据，不自动重新生成整个功能。

## 项目人工交接与批次衔接

人工要求引用现行宪法及其引用的验收、审批和发布约定，再核对本次验收场景；默认不新增最终人工验收。完整字段及执行权限沿用本次中文人工交接输入，已有覆盖不重复，当前环境不足的自动化测试仍保持自动化归属并记录阻塞原因。

需要混合任务或显式依赖时，在原 `tasks.md` 使用 `<!-- repo-sdd:hybrid-tasks:v1 -->`；类型标签后按需加入 `[人工]`。缩进字段使用“依赖”“类型”“负责人”“环境”“原因”“步骤”“预期”“证据”“发布必需”，确需正式签收才使用“最终验收：是”。保留显式停用标记及旧清单读取兼容性，无人工任务不输出空分组。

执行入口按当前 Spec Kit 项目指南核实，使用 `workflow/run.ps1 inspect-tasks --tasks <仓库相对路径>`，或同目录 `python -B runtime.py inspect-tasks --project . --rules <当前规则快照> --tasks <仓库相对路径>`。按本次输入读取 `result_version: 2` 及 `selected_tasks`，核对 `batch_remaining_ai`、`batch_pending_manual`、`ready_ai`、`blocked` 和 `batch_status`；非法范围或依赖先处理，不回退为全量执行，不扩大授权范围。

只推进获准的 `ready_ai`，更新 Agent 任务后重算，人工复选框保持原样。`batch_ai_complete` 仅指范围内 Agent 任务完成；`execution_batch_complete` 要求所选全部任务完成且无结构或依赖问题。全局状态核对整份清单；检查成功、任务勾选或批次完成不能把 `verification: unverified` 改写为测试、覆盖率或 CI 通过。

交接在对话说明批次范围、完成和剩余 Agent 数、待人工项、阻塞原因、实际自动化结果、可交接范围和下一步。人工结果、延期及正式签收由授权人员按现行约定记录；仅在实际复核后填写“实施复核”和当前“复核修订”。不新增平行状态文件，不批量改写历史记录。
