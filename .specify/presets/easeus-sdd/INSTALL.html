INSTALLATION & USAGE
解压后从 README 的第1步开始。项目参数由配置工具管理，预设通过 Spec Kit 的正式组合机制安装。示例命令不会在本页执行。

双底座中文 TDD · Spec Kit Preset

版本：1.0.0。适用于已有代码仓库，支持 Claude Code 与 Codex Desktop。 声明兼容 Specify CLI ≥1.1.3、<1.2.0；实际测试版本为 1.1.3。 配置工具使用 Python 3.11+ 标准库，无额外 Python 依赖。

你会得到什么

  • 9 个阶段命令采用 wrap，保留原工作流并加入阶段路由与质量约束。
  • 5 个产物模板采用 append，保留原模板并补充证据、测试和完成条件。
  • 默认中文；Wiki 提供背景，CodeGraph 定位代码，当前源码与运行结果核实结论。
  • TDD；仅新增生产代码的单元测试行覆盖率 ≥80%，不要求存量或全项目达到80%。
  • 防止占位成功、恒真断言、mock 被测核心逻辑和无证据勾选任务。
  • 一个可重复执行的项目配置工具：安装、改参数、生成提示词、生效检查、卸载。

预设不包含 CodeGraph/OpenDeepWiki 服务，不会自动建索引、更新 Wiki、 初始化 Git、升级软件、信任项目或绕过权限。 MCP 必须已经有真实部署/启动方法；可以只登记已有工具或 CLI，不重复配置连接。

这不是强制执行沙箱。 提示词政策不能从技术上阻止 Agent 写空测试。 必须通过真实测试、反向验证和适用的 CI/评审判断完成； doctor 仅检查配置与物化指令，不认证工具连接、覆盖率或业务正确性。

1. 解压和前置检查

把压缩包解压到固定目录，例如 D:\Tools\easeus-sdd， 在该目录打开 PowerShell。以下示例请替换路径和底座信息。

powershell
python --version
specify version --json
specify init --help
specify integration install --help
python -X utf8 .\scripts\sdd_preset.py --help

尚未安装 Specify CLI 时，按团队选择安装已验证版本：

powershell
uv tool install 'specify-cli==1.1.3'

已有 CLI 不重复安装，不自动升级。安装并登录实际使用的 Agent， 准备项目的编译器、构建和测试环境。Codex Desktop 不必另起 Codex CLI 会话； codex 是 Spec Kit 的集成键，项目技能会由桌面项目会话使用。

2. 仅在项目尚无 .specify 时初始化

在目标代码仓库中执行，已有 .specify/ 直接跳到第3步。

powershell
Set-Location -LiteralPath 'D:\Repos\your-project'
specify init --here --integration claude --script ps --non-interactive

初始集成也可以选 --integration codex --integration-options="--skills"。 Linux/macOS 可按实际环境使用 --script sh，包内 Python 工具跨平台， 下面的多行终端例子使用 PowerShell 语法。

非空目录可能要求 --force。先检查既有文件和潜在覆盖，再依实际帮助处理； 不要默认加 force，不重新 init 已初始化的项目，也不启用 Git 扩展来满足流程。 若只是生成集成文件、实际 Agent 在另一入口运行，可按当前版本支持的 --ignore-agent-tools 跳过 CLI 探测；它不等于已经验证 Agent。

3. 安装到指定项目

回到解压后的包目录，执行：

powershell
python -X utf8 .\scripts\sdd_preset.py install --project 'D:\Repos\your-project' --agents both --default-agent codex --repository-id 'my-team/my-project' --codegraph-index 'D:\Indexes\your-project' --codegraph-access '已配置的 CodeGraph MCP；projectPath 指向本项目' --wiki-location 'https://your-wiki.example/OWNER/REPO' --wiki-access '已配置的 OpenDeepWiki MCP 或文档读取入口'

将示例地址换成真实仓库入口。也可以用 --settings 'D:\Config\project-settings.json' 提供 JSON 补丁，省去长参数；examples/project.example.json 给出完整结构。 初次安装不提供来源信息也能完成注册，但上下文未配置，Agent 必须报告缺项。

安装工具会：

  1. 检查 CLI 版本、已有项目、配置类型和同名 MCP 冲突。
  2. 补齐缺少的所选集成，安装本地预设，不使用 --force。
  3. 分别激活 Claude/Codex、核实实际阶段技能，再设置你指定的默认集成。
  4. 把项目参数存入 .specify/easeus.json。
  5. 合并 AGENTS.md 受管理区块，CLAUDE.md 导入 @AGENTS.md， 保留其他原有内容；已有独立导入时避免重复。
  6. 对配置工具改写的已有文件保留项目内备份。

这是本地目录安装，不是向官方目录发布。CLI 会复制整个包到 .specify/presets/easeus-sdd/；以后改项目参数不用重新安装。 只用一种 Agent 时可选 --agents claude --default-agent claude 或 --agents codex --default-agent codex。

如果另一高优先级 Preset 或项目 override 覆盖了命令，安装检查会报未生效， 不会强制覆盖。先检查 specify preset resolve plan-template 等结果， 再决定优先级或如何组合已有规则。 安装过程不是跨 CLI 操作的事务；中途失败可能保留已安装的集成或预设。 按错误检查状态，修正后继续；不要反复强制重装。

4. 后续修改路径与底座

参数属于本工具，不是 /speckit-* 的原生参数。

powershell
python -X utf8 .\scripts\sdd_preset.py configure --project 'D:\Repos\your-project' --codegraph-index 'D:\Indexes\new-index' --codegraph-access '实际工具名与参数说明' --wiki-location 'D:\Docs\your-project-wiki' --wiki-access '本地 Markdown 文档目录' --source-snapshot '源码版本或快照' --codegraph-snapshot '索引对应版本' --wiki-snapshot '文档对应版本' --baseline '明确的基准提交或源码快照'

项目迁移后，针对新路径重新 configure，核实底座是否仍对应正确仓库。 版本不知道就保留 unknown，不要用生成时间代替源码一致性。 来源可以是 MCP、CLI、Index 路径或可读取的本地文档；访问描述由 Agent 使用， 配置工具不会执行其中的命令。

--dry-run 可预览配置改动。配置工具的备份在： .specify/easeus/backups/<时间戳>/。 预设升级、卸载不自动删除项目配置与备份。不要在同一项目同时运行两次设置工具。 工具为备份目录和机器状态添加局部 .gitignore；它不会移除已经被跟踪的文件。 备份可能含原 MCP 配置，请按本地敏感文件管理，不将它作为共享配置发布。

配置参数速查

参数用途
--project目标项目的现有目录，须已有 .specify
--agents both/claude/codex安装或检查的 Agent 范围
--default-agent claude/codex安装结束时保留的活动集成
--settings FILE合并 JSON 配置，命令行字段优先
--repository-id明确的项目/仓库身份
--codegraph-access / --codegraph-index实际访问说明与 Index 位置
--wiki-access / --wiki-location实际访问说明与仓库文档入口
--source-snapshot / --codegraph-snapshot / --wiki-snapshot适用版本或快照
--baseline新增可执行代码行的比较基线
--write-mcp显式合并项目 MCP；不默认为开启
--priorityPreset 优先级，默认10；越小越优先

政策固定为中文、TDD、0.80 新增行门槛；配置不能静默降低。 已知构建/测试/覆盖率命令可写入 JSON 的 verification.known_commands 数组， 工具只提供上下文，不自动运行这些命令。

5. 可选：生成或合并 MCP 连接

如果两种 Agent 已经接通底座，无需使用此步骤。 配置中的 access 是访问说明，不能自动变成 MCP 服务。

复制 examples/http-settings.example.json 或 stdio-settings.example.json， 改为真实 URL/可执行命令和参数，再执行：

powershell
python -X utf8 .\scripts\sdd_preset.py configure --project 'D:\Repos\your-project' --settings 'D:\Config\actual-mcp-settings.json'

默认只生成示例：

  • .specify/easeus/mcp/claude.example.json
  • .specify/easeus/mcp/codex.example.toml

确认需要后，加 --write-mcp 合并真实配置：

powershell
python -X utf8 .\scripts\sdd_preset.py configure --project 'D:\Repos\your-project' --settings 'D:\Config\actual-mcp-settings.json' --write-mcp

Claude 使用项目 .mcp.json；Codex 使用项目 .codex/config.toml。 Codex 项目配置需要按客户端要求信任该项目，不自动修改信任设置。 同名服务器已有不同内容时，工具拒绝覆盖；其他服务和 TOML 注释保留。

HTTP 可提供 bearer_token_env_var，只存环境变量名，不存密钥； Claude 将其映射为环境变量引用，Codex 保存变量名。 环境变量须在 Agent 实际启动环境中可用。OAuth 按服务与客户端流程登录。 stdio 用服务供应方真实的 command / args，本包不编造启动参数。 工具不会启动 MCP，也不证明服务器连通或仓库范围正确。

打开新会话，在 Claude 的 /mcp 或 Codex 相应工具设置中确认服务； 然后让 Agent 实际查一份文档与一个真实符号，引用来源并核实源码。

6. 检查配置与生效

powershell
python -X utf8 .\scripts\sdd_preset.py doctor --project 'D:\Repos\your-project' --agents both
  • 退出0：结构和所选命令检查通过，仍可能有未知版本警告。
  • 退出1：生效检查失败；--strict-metadata 也会把元数据警告作为失败。
  • 退出2：路径、参数、文件或工具错误。

doctor 检查配置、注册/启用状态、共享锚点及18个技能中的政策/核心组合标记。 它不对真实 MCP、模型行为、业务语义或测试有效性作通过判断。 不要将它的退出码作为 SDD 实施完成的门槛替代品。

以下只读提示词应在两种 Agent 中分别执行：

text
读取当前项目指令、.specify/easeus.json 和预设 common.md。
列出实际加载的阶段入口。查询正确仓库的一份 Wiki 文档、
一个 CodeGraph 符号及关系，用当前源码核实。
说明适用版本、真实调用结果、一个已核实事实和仍未确认的事项。
无法调用时报告真实限制，不用配置文件冒充工具结果。

7. 建立或更新宪章

安装不改写现有 constitution.md。在 Agent 中显式调用：

Claude Code：

text
/speckit-constitution
按已安装 easeus-sdd 政策更新现有宪章。
保留有效项目原则，中文编写，明确真实 TDD、有效测试、
仅新增生产代码单元测试行覆盖率 ≥80%，并定义可检查的完成条件。
不要实施业务功能或自动补测。

Codex Desktop 使用 $speckit-constitution，其余输入相同。 如果旧项目只有 /speckit.constitution 点号命令，应先按安装版本的集成 维护方式检查/迁移；本包不通过删除旧入口来强制迁移。

8. 每个功能的日常 SDD

阶段你提供的自然语言输入主要底座/证据
specify用户、触发、期望、异常/取消、验收、非目标Wiki 背景；按需核实现状
clarify关注主题及对关键问题的回答先查事实，再问产品决定
plan技术/兼容约束、比较基线、验证环境CodeGraph + 当前源码
checklist需求质量的评审主题，可选规格与计划；按需查背景
tasksTDD 依赖、有效断言与完成条件复用计划；按需核实位置
analyze一致性关注点，可选文档为主，必须只读
implement任务范围与实际验证命令当前源码、真实测试与报告
converge最终实现及验证证据按有效工作流检查差距

以上是 Agent 命令后的文本参数，不是 CLI flags。 当前上游 converge 只追加任务，不修改应用代码。 本预设保留它的核心定义：有差距后运行 implement，再 converge。 若项目另有明确的自定义行为，以实际有效命令为准，不绕过写入边界。 自定义 checklist 的勾选是需求质量评审，不能被 implement 静默自批。

自动生成已填项目参数的提示词

powershell
python -X utf8 .\scripts\sdd_preset.py prompts --project 'D:\Repos\your-project' --agent claude --stage specify --feature '新功能名称' --requirements '用户行为与验收要求'
python -X utf8 .\scripts\sdd_preset.py prompts --project 'D:\Repos\your-project' --agent codex --stage all --output 'docs/sdd/prompts.txt'

支持所有9阶段及 repair-tests、handoff。 --constraints 提供明确约束，--focus 提供澄清/评审/实施范围。 未提供的需求保留中文占位符，不能直接当成完整需求执行。 导出文件只能位于所选项目内。 每功能目录按当前工作流解析，不能只凭 Git 分支名判断。

发现空测试时先使用 repair-tests 提示词审查并形成修复任务， 再 implement；不要用“全返回 true”或覆盖率数字宣告完成。 跨 Agent 使用 handoff，交接实际文件、版本、任务和证据； 不要让两个 Agent 同时修改同一工作目录的相同文件。

9. 更新、卸载和故障处理

只改项目路径或来源：使用 configure，不更新预设。 更新包：先备份有价值的定制和配置，使用旧包卸载，再用新包 install。 不建议把上游 preset update 当作有自动回滚的事务。

powershell
python -X utf8 .\scripts\sdd_preset.py uninstall --project 'D:\Repos\your-project'

卸载通过官方 CLI 恢复核心阶段指令，移除未被用户编辑的共享锚点。 用户编辑过的锚点保留并提示人工检查。 保留项目参数、备份、MCP 配置、Agent 集成、宪章和功能文件； 不会自动断开工具或删除源码。 若直接使用 specify preset remove easeus-sdd，请自行清理指向 已卸载预设的项目指令锚点，避免新会话继续引用缺失文件。

若规则不生效，检查：

  1. specify preset list --json 中安装/启用状态和优先级。
  2. 两种集成是否均执行过 specify integration use <agent>。
  3. 实际 SKILL.md 是否包含 easeus-sdd:policy:v1。
  4. 是否有更高优先级 override 或自定义阶段入口。
  5. 是否打开了错误项目或仍在使用旧会话。

preset disable 不一定移除已经物化的命令；本工具 doctor 会把禁用状态报错。 需要停止整个预设行为时按卸载步骤处理，不仅禁用模板解析。

10. 测试与适用限制

powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 .\tests\smoke_specify.py --work-root 'D:\Temp\sdd-smoke' --initial-agent claude
python -X utf8 .\tests\smoke_specify.py --work-root 'D:\Temp\sdd-smoke' --initial-agent codex

集成测试仅在新建的隔离目录内初始化 Spec Kit，不初始化 Git； 需要真实 Specify CLI，但不执行 LLM、MCP 或业务测试。 --work-root 必须位于包目录外。只清理本次创建并核实范围的测试目录。

参考核验：2026-10-15。实际 CLI 测试结果见 docs/VALIDATION.json。 本文不宣称所有未来 CLI 版本、企业权限设置或 Agent 执行行为都相同。
