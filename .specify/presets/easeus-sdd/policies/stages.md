# 阶段路由与完成边界

|阶段|Wiki|CodeGraph / 当前源码|应形成结果|
|---|---|---|---|
|constitution|背景、术语、已有流程|Wiki 建背景；CodeGraph 核实关键工程事实。|constitution.md、版本与修订说明；实际要求的 Sync Impact Report。|
|specify|背景、术语、已有流程|Wiki 为主；CodeGraph 按需核实影响需求的现状。|当前 feature 的 spec.md；工作流可能维护内置 requirements checklist。|
|clarify|背景、术语、已有流程|按问题查两个底座；产品决定交给用户。|更新 spec 和工作流允许维护的内置检查状态。|
|plan|按需补充|CodeGraph 与当前源码为主，Wiki 提供架构背景。|plan.md 及工作流需要的 research/data-model/contracts/quickstart 等。|
|checklist|按需补充|工作产物为主，必要时查底座。|自定义 checklist，不是实现任务或测试报告。|
|tasks|按需补充|复用 plan，按需用 CodeGraph 核实位置和依赖。|tasks.md，保持工作流规定的 ID 与结构。|
|analyze|按需补充|文档为主，必要事实再查底座。|分级报告与修正建议，不修改文件。|
|implement|按需补充|CodeGraph 和当前源码为主，Wiki 按需补充。|代码、测试、任务状态与可复核结果。|
|converge|按需补充|当前源码与运行证据为主，CodeGraph 辅助，Wiki 解释背景。|差距及后续工作。当前上游默认只追加 tasks，本地定制以实际为准。|
