# 赛程日期区间筛选

让用户在赛程页选择开始和结束日期，快速查看某一天或一段日期内的比赛，并与已有赛事阶段、“只看关注球队”组合使用。

本文是交给 `speckit-specify` 的需求输入草案。功能名称固定为“赛程日期区间筛选”；后续规格、计划和任务由相应阶段生成。本次推荐不代表功能已实现或界面设计已获批准。

## 用户价值与范围

用户准备集中浏览某几天的比赛时，目前只能按阶段和关注球队缩小范围，仍需逐张查看比赛日期。本次在现有赛程页增加日期条件，无需新增页面或外部服务。

- 范围内：日期输入与应用、边界校验、组合筛选、单独清除日期、结果与空态反馈，以及中英文、键盘和窄屏适配。
- 范围外：日历月视图、按用户时区换算比赛日、日期快捷预设、日历导出、开赛提醒、登录和云同步。
- 日期条件仅在当前页面会话内保留，不新增分享链接参数或浏览器持久化记录；现有关注列表的保存方式保持兼容。
- 主要风险：比赛日被误作本地时区日期、非法区间被当成零场比赛、清除日期时误清其他筛选，以及页面重渲染导致输入或焦点丢失。

## 用户故事与验收

### US1：查看指定日期范围的比赛

用户在赛程页填写日期并主动应用，得到与所选比赛日一致的结果。

**FR-001：选择并应用日期。** 增加有明确标签的“开始日期”“结束日期”、一个“应用日期”按钮，以及显示当前已生效日期条件的文字。首次进入时两项为空，表示不限日期。编辑输入不会立即改变比赛列表；存在尚未应用的修改时，显示“日期尚未应用”。成功应用后，列表、比赛数量及已生效条件同步更新。

| 验收编号 | 前置条件与操作 | 可观察结果 |
| --- | --- | --- |
| AC-01 | 首次进入赛程页，不填写日期 | 显示“不限日期”，结果由现有其他筛选决定 |
| AC-02 | 输入有效开始、结束日期，尚未点击应用 | 列表和数量保持上次结果，显示“日期尚未应用” |
| AC-03 | 点击“应用日期” | 结果仅包含区间内比赛，数量等于实际显示的不同比赛数，摘要显示本次生效区间 |

**FR-002：日期按比赛快照中的比赛日判断。** 起止边界均包含当天，不根据当前日期、设备时区或比赛时间字符串推算日期；界面在日期控件旁说明“按赛事数据中的比赛日期筛选”。支持以下输入：

| 日期条件 | 筛选结果 |
| --- | --- |
| 两项均为空 | 不限制比赛日期 |
| 仅开始日期有值 | 比赛日期大于或等于开始日期 |
| 仅结束日期有值 | 比赛日期小于或等于结束日期 |
| 两项为同一天 | 仅显示当天比赛 |
| 开始日期早于结束日期 | 显示包含两端日期的整个区间 |
| 有效日期落在赛事日期范围外 | 正常筛选，可得到零场；不自动改为赛事首日或末日 |

验收 AC-04：使用日期分别为 `2026-06-11`、`2026-06-12`、`2026-06-13` 的受控比赛样例，依次验证表中各条件。区间 `2026-06-11` 至 `2026-06-12` 只包含前两天；两端均为 `2026-06-12` 时只包含第二天。更换浏览器时区后，匹配的比赛 ID 集合不变。样例仅用于验证，不要求改写赛事快照。

**FR-003：拒绝无效输入并保留上次有效结果。** 日期须为真实存在的公历日期，内部比较采用 `YYYY-MM-DD` 的日期含义，控件的可见格式可遵循浏览器本地化。非空但不完整、不存在的日期，或开始晚于结束，均不能应用。不得静默交换日期、截断范围或把校验错误显示为“没有比赛”。

验收 AC-05：已有一个有效区间时，输入 `2026-06-13` 至 `2026-06-11` 并应用，保留输入和上次已生效结果，在结束日期旁显示“结束日期不能早于开始日期”，焦点移至结束日期。对不完整或不存在的日期，显示“请输入有效日期”，关联相应字段并聚焦第一个无效字段。修正输入后重新应用可成功，旧错误消失；输入仍与已生效条件不同时保留未应用提示。

### US2：组合筛选并快速恢复结果

用户在所选日期内继续筛选阶段和关注球队，或单独移除日期限制。

**FR-004：三个筛选条件取交集。** 日期、赛事阶段、“只看关注球队”同时生效。调整阶段、关注开关或关注列表时，使用当前已生效日期条件重新计算结果，不自动应用尚在编辑的日期。比赛双方都被关注时仍只显示一场，结果保留现有阶段／小组组织及组内顺序。

验收 AC-06：准备“区间内且满足其他条件”“区间外但满足其他条件”“区间内但阶段不匹配”“区间内但不涉及关注球队”的比赛，组合筛选只显示第一类。第一类比赛双方都被关注时，卡片和计数均不重复。修改阶段或关注条件后，日期输入草稿及已生效日期摘要仍各自保持。

**FR-005：清除日期与空态恢复。** 日期控件区始终提供“清除日期”按钮。一次操作清空两项日期输入、已生效日期限制、校验错误和未应用提示，并立即重新计算结果；保留阶段、关注开关及关注列表。已经不限日期时再次清除，状态不变。

验收 AC-07：在“日期＋阶段＋只看关注球队”的组合下清除日期，结果等于仅应用后两个条件的结果，摘要恢复“不限日期”。有非法输入时也可直接清除，无需先修正。

验收 AC-08：合法组合得到零场时，数量显示为零，不渲染空的比赛分组。已开启关注筛选且没有关注球队时，保留“尚未关注球队”的提示及选择球队入口；其余情况显示“当前筛选条件下没有比赛”。日期控件和清除入口仍可使用，且不暗示清除日期一定能得到比赛。

### US3：切换语言和页面后继续浏览

用户在同一页面会话内切换语言、主题或查看比赛详情时，能够理解并继续使用日期筛选。

**FR-006：明确状态保留边界。** 切换中英文或主题、调整其他筛选引起的重渲染，不丢失已生效日期、输入草稿和校验状态。离开赛程页时放弃尚未应用的编辑；同一标签页内返回赛程页，恢复已生效日期，输入与生效条件一致。整页刷新或新开标签页后，日期恢复不限，不要求跨标签页同步。

验收 AC-09：分别在有效筛选、未应用编辑和输入错误状态切换语言，筛选结果不变，新增标签、说明、摘要、按钮、提示和错误均切换到目标语言。点击比赛进入详情后返回，恢复离开前已生效日期；整页刷新后日期为空，原有已保存关注列表不受影响。

**FR-007：支持连续键盘操作及清晰反馈。** 日期输入和两个操作按钮均有可访问名称，按页面阅读顺序可用键盘到达，按钮支持键盘激活。成功应用后焦点留在应用按钮，清除后留在清除按钮；错误焦点遵循 FR-003。上述操作不强制滚动到页面顶部。结果数量更新可被辅助技术感知。语言切换后保留语言切换控件的焦点，不将焦点抢到日期区。

验收 AC-10：仅用键盘完成输入、应用、修正错误和清除；连续操作或快速切换已有筛选时，以最后一次有效操作的状态为准，不出现旧结果覆盖新结果、重复触发或焦点落回页面根部。

## 界面约束与状态

这是现有赛程页的局部交互扩展，建议采用轻量 UI 流程。设计输入为本文文字及仓库现有组件；未提供设计图或已批准视觉稿，后续规格应据此记录拟定方案及确认范围。

- 日期区域放在现有筛选区域内、比赛列表之前。阅读顺序为开始日期、结束日期、应用日期、清除日期；日期口径说明、已生效条件和错误邻近对应控件。
- 沿用项目现有按钮、输入、提示和深浅主题风格；比赛卡片、球队徽标和阶段标签复用现有呈现。
- 在 `1440×900` 与 `390×844` CSS 像素视口、100% 缩放下检查中英文和深浅主题。窄屏允许控件换行，但不遮挡文字、不重叠、不因新增区域产生页面横向滚动；焦点指示可见。Chromium 为本次验证起点，不据此扩展正式浏览器支持承诺。
- 默认状态见 FR-001，输入错误见 FR-003，无结果见 FR-005。初次数据尚未就绪时沿用页面加载反馈，不展示可提交的日期控件；加载失败时沿用现有错误及重试入口，不显示为零场比赛。重试成功后使用会话内最后有效日期条件恢复结果。
- 日期筛选不额外发起网络请求；加载完成后的筛选没有独立加载状态。功能使用现有静态赛事快照，保留既有非实时、非官方说明，AI 服务不可用不影响筛选。
